7

Keep ownership visible

An owner can return to a publication, prepare an update, edit its current details, or delete it.

Deletion Deleting a modeling removes it and its version links. Deleting an account removes its publications. Already-published forks remain independent.
Proposal · Bounded history Count versions and stored bytes in quota usage, not just publication count. Do not silently prune cited versions.
Minimal moderation Reports go to the chosen email inbox with the modeling URL. Authorized accounts can unpublish; admins delegate permissions. No report queue is planned.
Account states to cover in the plan

Email/password sign-up, email verification, sign-in, and password recovery need distinct screens. An expired verification link should offer a resend; a failed email send must preserve the workspace. Successful verification returns to publishing. The provider, retention policy, and account-email-change behavior still need confirmation.

Decisions still to confirm

The main flow is specified. These are the remaining product boundaries; recommendations are not approvals.

Boundary Recommended starting point
Existing workspace Use a free slot; otherwise ask before replacement. Viewing a shared URL never consumes or overwrites an editing slot.
Historical results Distinguish published results and engine version from any later recomputation. Decide the extent of reproducible historical exploration.
Metadata and citations Snapshot version attribution; current listing details remain editable. Agree how later corrections and attribution-removal requests affect old citations.
Deletion and provenance Reserve retired URLs; preserve appropriate source/version/license citation data in forks and exports. Decide takedown/restoration behavior.
Storage and concurrent updates Count history in quotas; reject stale-base updates with an explanation and retain the working copy.
Viewing preferences Carry valid preferences across versions; offer reset to published defaults and use the current view when forking.
Publish readiness Require computable results and keep user input intact when publication fails.

Before production: agree the report inbox, responsible administrator, transactional-email service, license and embedded-data compatibility, privacy and retention terms, and board approval. This prototype does not send a report.

Implementation pointers and review context

Prospective design for public-model-sharing/spec.html. The license proposal remains a board decision. Mocked values are illustrative. This file is self-contained and makes no network requests.

Grounding in the existing interface
theme/templates/navbar.html supplies the existing logo, Documentation, and Feedback buttons. The logo and toolbar SVGs are embedded directly from theme/static/images/ and theme/static/icons/tooltip/; no remote assets are required. model_builder/components/model_tab_strip.html places the two modeling tabs above upload_download_reboot_model_tooltips.html's per-modeling toolbar. components/edge_modeling_toggle.html, components/help_menu.html, and components/show_results_toolbar_button.html supply the toggle, menu contents, and results CTA. The one-model toolbar is shown; with two modelings the existing export menu offers “⬇ This modeling” and “⬇ Both modelings”. model_builder_main.html places the canvas, right-hand side panel, and results panel. Chrome checked against these templates on 21 September 2026. New Explore, account, and publication actions are explicitly marked proposals; “My publications” is a proposed account-menu entry, not an existing navbar link.
Public state and personal state
Public requests hydrate ModelWeb normally. The publication snapshot and its interface defaults are protected. Visitor presentation overrides are separate, session-scoped state keyed to the shared modeling. The prototype simulates changes in memory only; reload restores the example.
Two builder destinations
Forking loads an independent copy; editing an owned publication retains its publication/base-version association for an explicit update. Both use /model_builder/. A full workspace requires a product decision before implementation.
Demonstration controls
The publish form previews a slug and simulates a taken address using already-taken. The reader screen changes sample version totals and viewing preferences, previews owner actions, and shows citation links. Explore filters illustrative titles. No backend, authentication, durable storage, or clipboard access is implemented by this document.
