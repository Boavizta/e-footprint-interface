share-a-model Web + edge Prospective — not built

⚠ Prospective journey — target-state design, not the deployed app.
Normative design for the public-model-sharing feature (spec: specs/features/public-model-sharing/spec.html, license draft: content-license.md alongside it). Today nothing survives the 12-hour session cache except a JSON download (save-and-load stays the faithful description of persistence). At ship time the publish entry folds into the builder toolbar, the public/explore pages become faithful journeys, and the banner comes off. Capability decisions locked in the spec (2026-07-07): public-by-construction, all listed, latest + immutable version permalinks, thin email-only accounts, CC BY 4.0 pending board validation.

Today a modeling is a private, perishable session: to show it to anyone you send a file. share-a-model turns a modeling into a citable public page: publish it under a stable link, let anyone read it with full explainability and fork it into their own session without an account, and let the world find it on an Explore page. Success is a company publishing a living account of its ecodesign work, a journalist citing a version permalink that can never silently change, and a reader one click away from challenging any hypothesis in their own copy.

Publishing requires a thin account (an email, nothing else) — viewing and forking never do. There are no private saves: the session and the JSON file remain the only private workspaces. Code-level pointers in Implementation pointers.

1

Publishing is the only thing that needs an account

The account exists solely so the publisher can later update or delete what they published — no volunteer in the loop. It is deliberately thin: a verified email and the public author name they'll choose at publish time. The barrier stays where it protects (writing to Boavizta's database) and away from where it would hurt adoption (reading, forking).

Thin accountEmail only — verified by a sign-in link. No password stored (leaning; the mechanism is a plan-stage call, the "email is the only personal data" promise is not).
Verification gatesYou cannot publish until you've proven control of the email — the first anti-abuse wall.
Consent up frontAccount creation shows the privacy notice: what's stored (the email), why, and how to erase it.
Model not computable?↗ Publish is disabled with a tooltip reason until the model computes — disabled-not-errored, applied to publishing.
Edge paradigmIdentical flow — a modeling is a modeling; web and edge publish the same way.

2

Describe it, acknowledge what public means, publish

Four fields and one honest warning. The amber box does the legal work in one breath: public by construction, listed, forkable, CC BY 4.0 — so nobody publishes thinking they saved a private draft. The article link closes the loop with the written piece that will cite this modeling.

Curated tagsPick from a maintained list — no free-text tags, so Explore filters stay meaningful. Extending the list is a maintainer action.
Author nameFree-text, deliberately public, required. The email never appears anywhere public.
License at the point of grantCC BY 4.0 acknowledged here, not buried in terms — with the right-to-publish warranty (see content-license.md).
Quota-boundPer-account limits on modeling count, size and publish rate. At the limit, Publish is disabled with the reason — the anti-overflow wall, invisible to honest users.

3

A link you can put in print

The payoff artifact is the URL. The canonical link always shows the latest version; every published revision keeps an immutable permalink — so a company hands out one evergreen link while a researcher cites an exact state. The dialog says both in plain words at the moment the user needs them.

Canonical linkOne readable URL per modeling — follows the latest version forever.
Version permalinksEach publish freezes an immutable snapshot with its own link — citations can't silently drift.
Session unchangedPublishing copies the model out; the session keeps its 12-hour life and stays the private editing space.

Read-only, but nothing hidden

The reader gets the full explainability contract — canvas, results charts, Sankey, sources, the derivation of any number — because auditability is the product being shared. The header carries the trust signals a citation needs: author, date, version, license. No account, no cookie wall, no watermark.

Version visibleThe selector states which version you're reading and that history exists — switching goes to that version's permalink.

5

The fork is the conversation

Disagree with a hypothesis in a published modeling? Fork it, change the number, watch the results move — the peer-review gesture the whole feature exists for, and it costs a click. Collaboration happens by forking, never by co-editing: every fork is an independent modeling with its own owner.

No account to forkForking lands straight in an anonymous session — the account wall only returns if they choose to publish the fork.
Original untouchedA fork is a copy. Nothing a forker does reaches the source modeling — and deleting the source never reaches published forks.
Session rules applyThe fork is ephemeral like any session model: export it or publish it to keep it.
Fork provenanceWhether a published fork shows "forked from X (v3)" — open spec question; capture-at-fork-time is cheap, reconstruction later impossible.

7

The author keeps agency over public data

Updating reuses the loop the user already knows: load into session, edit, republish — the canonical link moves to the new version, permalinks preserve the old ones. Erasure is immediate and self-service: public doesn't mean surrendered. Deleting the account deletes its modelings and their share links; forks already published by others live on (CC BY 4.0 is irrevocable for existing copies — stated plainly at the confirm).

Update = republishOpen in session → edit → Publish update. Same form, pre-filled; mints version n+1 and a new permalink.
Metadata editsTitle / tags / article link change in place without a new version — the content is versioned, the card is curated.
Delete a modelingImmediate; the link and all its version permalinks go away. The confirm restates the fork caveat.
Delete the accountImmediate erasure of the email and every published modeling — the GDPR promise, self-service.
Quota, visiblyThe quota line makes limits legible before they bite; at the limit, publishing is disabled with the reason.

Decisions taken

DecisionWhy / why-not-X
Public by construction — no private or unlisted saves.A private-draft tier would turn Boavizta's database into a free private model store (the overflow-abuse vector) and muddy the data-ownership pitch. The session and the JSON file already are the private workspace.
Accounts gate publishing only; reading and forking are anonymous.The wall sits where it protects (writes to the shared database) and not where it kills the reach that motivates the feature (readers of articles).
Thin accounts: a verified email, nothing else.Boavizta has never handled personal data; "the only personal data is an email" is the whole board pitch. The public author name is user-chosen and deliberately public.
Canonical latest link + immutable version permalinks.Mutable-only links let citations silently drift (fatal for research use); immutable-only links break the "living transparency page" (fatal for company use). Both personas are served by the pair.
Everything published is listed on Explore.Complete-by-construction discovery, and unlisted links would reopen the quasi-private-storage channel.
CC BY 4.0 acknowledged in the publish form itself.The license is the reuse contract forking depends on; burying it in a terms page invites "I didn't know". One amber box, one checkbox (rationale: content-license.md).
Deletion is self-service and cascades; published forks survive.The author keeps agency over their data (no volunteer mediates erasure); forks are independent modelings under an irrevocable license — both halves stated at the moment of deletion, not discovered later.
Quotas + verified email + reactive report/unpublish — no editorial pipeline.Volunteer pre-moderation wouldn't scale and adds no value; quotas bound the database, verification prices out burner loops, and the report path covers the residual (also fits the technical-intermediary hosting posture).
The public page reuses the builder's view surfaces read-only.Explainability is what's being shared — a static export (PDF-like) would amputate it, and a bespoke public renderer would drift from the app. Strip editing, keep everything else.
⌗ Implementation pointers for agents — prospective: target shape + today's code anchors

Status: prospective. Normative for specs/features/public-model-sharing/ (spec.html locked 2026-07-07; license draft in content-license.md). Production activation is gated on Boavizta board approval — the feature must be demonstrable on dev.e-footprint.boavizta.org first.

Today's anchors
Toolbar (where ↗ Publish lands): the per-model toolbar mocked in build-a-model / save-and-load (open ↥ / export ⬇ live there). Read-only surfaces: the public page reuses the canvas, Results panel and derivation views described in view-results and audit-a-result with editing affordances stripped. Persistence: today only the encrypted session cache (12 h TTL) and the .e-f.json round-trip — published modelings introduce the first durable store (PostgreSQL is already provisioned on Clever Cloud; Django auth exists for admin only).
Target shape
Published modeling = immutable version snapshots (full system JSON) + mutable metadata row (title, tags, article link, author name, owner). Canonical URL resolves to the latest snapshot; /v<n> permalinks resolve to frozen ones. Fork = load a snapshot into a fresh session via the existing upload/deserialization path. Anonymous reads must be cacheable — pre-render or cache the public page; never rebuild the model per request (the app's binding constraints are store weight and round-trips). Old snapshots ride the same schema-upgrade path the JSON upload already uses.
Accounts & legal
Email-only identity, verification link gate before first publish; auth mechanism (magic-link vs password) is a plan-stage decision — the "email is the only stored personal data" constraint is not. Outbound email is a new operational dependency either way. Consent + privacy notice at sign-up; erasure cascades account → modelings → snapshots. Quota values are plan-stage.
Supersession
At ship: the publish entry folds into the builder journeys' toolbar anatomy; Phases B/D/E become faithful journeys (public page, explore, my-modelings); banner and hub pill come off.
