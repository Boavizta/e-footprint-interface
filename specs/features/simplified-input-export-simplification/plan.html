Simplified-input export simplification

Spec under review · Paths are relative to the interface repository root.

This captures the agreed simplification from the kickoff. It authorizes no application changes or tasks.

Export through ordinary autosave

Remove the export-specific mouse-press handler and the focused-edit branch of the capture click handler. Native focus movement will reach the existing numeric focusout save or source-editor focusout completion. The shared control lock and interaction suppression block export during that write. After settlement, the user activates Export again. Reuse the existing export admission path for the Configure check below; do not introduce another coordinator or a queue.

Delete completeFocusedEditForExport(), pendingExport and the export continuation in the second settlement listener. Keep its timeseries-panel closure. Remove the export callback from createFieldEdits() and its composition call.

Keep saveEdit(), the accepted-form/status settlement listener and _rejected_simplified_input(). Export no longer invokes field validation; an invalid draft can coexist with a download of the repository's saved state.

Delete continueExport() entirely once both inline-edit and Configure export callers are removed. The toolbar links and menu keep their current destinations and mutation-guard markers.

Scope boundary: the separate mutation-gate draft replaces blanket locking with write cancellation and uses the same saved-state export policy. Focused-edit completion, pending export, successful-save continuation and export-specific invalid-edit blocking are removed. Configure exports also have no continuation: dirty configuration blocks export, and clean configuration exports directly. One active write, busy-export blocking and Configure exit protection for other navigation remain. Coordinate the overlapping changes once: if the guard changes first, use its narrow export admission check; if export simplification lands first, preserve that behavior when replacing the guard.

Export from Configure

Replace the Configure export branch with a synchronous admission check against the existing configureForm() dirty state. If Configure is dirty, suppress the activation and show concise feedback to save or discard using existing controls. Do not submit the form, open the exit dialog, leave Configure or retain the export target. Keep the check before delegated dropdown activation so both menu opening and download links obey it. The shared write guard continues to block exports during saving.

Exclude [data-workspace-export] controls from the generic Configure click/exit interception. Otherwise a dirty export can still become deferred navigation, and a clean export can trigger an unnecessary saved-view load. Clean Configure exports must follow the native link or menu action directly, without changing the Configure screen. Audit all single-model/workspace entry points and their mouse/keyboard ordering against both guards.

Preserve deferExit(), pendingExit and replayClick() for other Configure exits. Save / Discard / Stay and successful-save navigation still serve those actions. Remove their unused bindings from the export entry point after export no longer uses them. Saving, discarding, staying or a rejected Configure save must never resume a blocked export.

Adapt the focused-edit export test to cover a blocked activation, no automatic download after success, and a later activation exporting final value/provenance. Retain rejection/restoration coverage; change the invalid-edit expectation to export the previous saved value.

Adapt the single/two-model activation test: a mouse press may now start ordinary autosave even if the gesture is abandoned, but cannot cause a deferred export. Cover keyboard activation and the menu after settlement, and retain non-export Configure exit regressions. Replace the related Jest export cases with observable saved-state and manual-activation expectations. Tests listed here are planned, not executed.

Add Configure export coverage for clean and dirty forms, single-model/workspace downloads and the two-model menu, using mouse and keyboard activation. Dirty activation must show feedback without downloading, opening the menu, sending a save or saved-view read, or opening the exit dialog. Save and discard must leave no queued download or menu opening; a fresh Export activation works afterward. A rejected Configure save retains its draft and blocks Export. With clean Configure and no write, exporting works directly without replacing that screen. Retain the existing other shared-exit regressions and successful-save navigation continuation coverage.
