Simplified-input export simplification

Feature spec · Paths are relative to the interface repository root. Reviewed interface range: 751511d97767857e3ca45d86847e65e52fe42e20..e554cc700ff315f0910b1de2c86f95528632b889; library unchanged at e3ab9f4a1107710955c13cdcf6d3ee991e33a4dd.

Exports use accepted repository state. Ordinary inline saves continue as before; an export gesture during a write is consumed without replay. Dirty Configure blocks export in place, and a fresh activation after the user resolves the draft performs the export.

Export through ordinary autosave

Implemented as planned. Ordinary inline edits save on focusout or Enter, and provenance changes use the same save path. There is no focused-edit completion or stored export continuation: module composition passes only active-workspace access to createFieldEdits(); save settlement records accepted status and closes a completed timeseries panel. The fresh-activation regressions link the removed continuation behavior to its current evidence below.

const workspace = createWorkspace();

Native focus movement reaches the numeric focusout save or source-editor focusout completion. Provenance completion writes the hidden fields and dispatches its change event, consumed by the ordinary provenance save listener. A valid changed field synchronously starts HTMX; the mutation admission calls begin() before the later click. Its control lock disables the menu button and removes download destinations; its capture suppression blocks export activation until finish() restores controls. There is no download or menu opening at settlement. If the save finishes before activation, that activation may proceed.

A scoped Chromium diagnostic checked event ordering with a rendered editor fixture, HTMX, source metadata, field edits and the shared guard. The final browser regressions also hold server responses while checking real focus and downloaded content; see the named tests in verification.

saveEdit() retains native validation. An idle export does not validate or submit a focused draft, so a browser-invalid draft remains unsaved and the file contains its previous accepted value. A rejected server save restores the accepted field and shows the existing error through _rejected_simplified_input(); after dismissing it, a fresh activation exports accepted state. Native invalidity can return focus to the input and, for two models, open the export menu before a fresh link activation; the browser regression checks the accepted download. Completed timeseries settlement still closes its panel at the second mutation-finished listener.

The toolbar already marks the two-model toggle and links and single-model link for the shared guard. No toolbar or server change is needed. download_json() and download_workspace() hydrate repository state through _single_model_document(); no browser draft enters their payloads. This follows Persistence: export boundary and Rendering: shared mutation guard.

Export from Configure

Implemented as planned. The window-capture listener checks the existing configureForm() dirty flag, before Bootstrap's document-capture dropdown handler. The flag is set by Configure edits; no second baseline or state store was added. During a write the shared guard owns busy suppression. Dirty Configure blocks both opening the menu and activating either download link; clean Configure permits the native action and stays open.

theme/static/scripts/simplified_inputs/index.js · Implemented excerpt · notice update included

window.addEventListener("click", event => {
    const element = event.target.closest("[data-workspace-export]");
    if (!element || document.body.dataset.workspaceMutation === "updating") return;
    if (workspace.configureForm()?.dataset.dirty !== "true") return;
    event.preventDefault();
    event.stopImmediatePropagation();
    const notice = document.createElement("p");
    notice.setAttribute("role", "status");
    notice.dataset.simplifiedNotice = "";
    notice.textContent = "Save or discard Configure changes before exporting.";
    const activeWorkspace = workspace.activeWorkspace();
    activeWorkspace.querySelector("[data-simplified-notice]")?.remove();
    activeWorkspace.querySelector(".simplified-header").after(notice);
}, true);

The listener replaces the active workspace’s existing notice with one status paragraph after its header, using the same notice marker. It sets the text to Save or discard Configure changes before exporting. Configure’s header and Save/Cancel controls provide the location and actions. Repeated blocked activations replace the message; saving or completing discard replaces the workspace and removes it, while a failed save preserves the form, notice and dirty flag.

The generic Configure click interceptor excludes exports before pending-read cancellation and exit deferral. The exclusion covers a clicked export control or its descendant, so clean download links and the dropdown toggle do not load the saved Simplified view or enter Save / Discard / Stay.

Its narrow busy check must run before menu activation and download links. The gate redesign was not a prerequisite for removing continuation; its cancellation work stays outside this feature.
