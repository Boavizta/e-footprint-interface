Simplified-input export simplification

Spec under review · Paths are relative to the interface repository root.

This captures the agreed simplification from the kickoff. It authorizes no application changes or tasks.

Export through ordinary autosave

Remove the export-specific mouse-press handler and the focused-edit branch of the capture click handler. Native focus movement will reach the existing numeric focusout save or source-editor focusout completion. The shared control lock and interaction suppression block export during that write. After settlement, the user activates Export again. Do not introduce another export handler or a queue.

Delete completeFocusedEditForExport(), pendingExport and the export continuation in the second settlement listener. Keep its timeseries-panel closure. Remove the export callback from createFieldEdits() and its composition call.

Keep saveEdit(), the accepted-form/status settlement listener and _rejected_simplified_input(). Export no longer invokes field validation; an invalid draft can coexist with a download of the repository's saved state.

Preserve the Configure export branch, continueExport() and replayClick() where Configure still needs them. The toolbar links and menu keep their current destinations and mutation-guard markers.

Scope boundary: the separate mutation-gate draft replaces blanket locking with write cancellation and uses the same saved-state export policy. Focused-edit completion, pending export, successful-save continuation and export-specific invalid-edit blocking are removed; one active write, busy-export blocking and Configure exit protection remain. Coordinate the overlapping changes once: if the guard changes first, use its narrow export admission check; if export simplification lands first, preserve that behavior when replacing the guard.
