Simplified-input export simplification

Status: Spec — under review · 2026-10-12

Small follow-up to Simplified inputs · Kickoff draft plan

1. Problem and audience

Export currently completes a focused Simplified-input edit and resumes the export automatically after a successful save. This adds browser coordination for a convenience that the user considers unnecessary. People exporting a model can wait for its ordinary autosave to finish and activate Export again if their first activation was blocked.

The goal is to simplify this behavior while preserving normal saves, error feedback and reliable exports of the saved model.

2. Success criteria

  1. In ordinary Simplified-input editing, Export downloads the model's accepted saved state. It does not force a focused edit to save, retain an export request, or resume a blocked export when a save finishes.
  2. Leaving a valid changed inline value or provenance control still triggers its ordinary autosave. If that save is running when Export is activated, no file downloads. After the save completes, a fresh activation works. If the save has already completed, Export may work on the first click.
  3. During an active workspace write, single-model and whole-workspace exports remain unavailable. The existing saving feedback remains; no extra export confirmation or recovery control is introduced.
  4. A server-rejected save still shows its error and restores accepted fields. It never triggers a download on completion. After dismissing the error, a fresh activation exports the accepted state.
  5. A browser-invalid edit remains unsaved. When no write is active, Export may download the previous saved state without an export-specific validation warning. It does not save the invalid edit.
  6. Mouse and keyboard activation use the same saved-state policy. Outside Configure, opening the two-model export menu does not schedule a later menu opening or download. Existing Configure exit protection and exports of saved values from unfinished Modeling or timeseries panels continue to work.

3. Scope

In scope

Simplified-input inline value/provenance edits followed by the ordinary single-model or whole-workspace Export action; repeated activation after a save; saved-state export after browser validation failure or server rejection.

Out of scope

Redesigning the shared workspace write policy, autosave, validation, accepted-field restoration, Configure exits, file formats or server persistence. No new export queue, automatic retry, unsaved-export dialog or UI control.

4. UX / interface

5. Constraints

Stay within the mission and constitution, particularly minimal browser JavaScript. Preserve one active workspace write, block exports during that write, and retain accepted-state ownership described in Persistence and Rendering.

This intentionally replaces the original Simplified-input requirement to finish a focused edit before export, resume export after saving, and cancel export for a browser-invalid edit. The workspace mutation-gate spec uses the same saved-state export policy defined here. Both features retain one active workspace write and block exports during that write; Configure keeps its existing exit protection.

6. Open questions

No product decision remains from the kickoff. Requiring another activation after a blocked click and allowing export of the previous saved state while an edit is invalid are accepted tradeoffs. Planning must verify the ordinary focus/save ordering against the current checkout.
