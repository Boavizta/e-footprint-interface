Simplified-input export simplification

Status: Implemented · 2026-10-12 · Outstanding validation prerequisites

Small follow-up to Simplified inputs · Implementation review guide

1. Problem and audience

Export currently completes a focused Simplified-input edit and resumes the export automatically after a successful save. This adds browser coordination for a convenience that the user considers unnecessary. People exporting a model can wait for its ordinary autosave to finish and activate Export again if their first activation was blocked.

Configure also postpones Export through its Save / Discard / Stay exit flow. The same simplification applies there: block Export while configuration changes are unsaved, let the user resolve them through the existing controls, and require a fresh Export activation afterward.

The goal is to simplify this behavior while preserving normal saves, error feedback and reliable exports of the saved model.

2. Success criteria

  1. Export downloads the model's accepted saved state. It does not force a focused edit or Configure draft to save, retain an export request, or resume a blocked export after saving or discarding.
  2. Leaving a valid changed inline value or provenance control still triggers its ordinary autosave. During that save, the two-model Export toggle is disabled. Native links already available can download saved state; the file includes the edit only if its persistence finishes first. Saving never triggers a download.
  3. During a field save, the one-model direct link and pre-opened two-model menu links retain their native destinations. A closed two-model menu cannot newly open. The existing saving feedback remains; no extra export confirmation or recovery control is introduced.
  4. A server-rejected inline save still shows its error and restores accepted fields. It never triggers a download on completion. After dismissing the error, a fresh activation exports the accepted state.
  5. A browser-invalid inline edit remains unsaved. Export may download the previous saved state without an export-specific validation warning. It does not save the invalid edit.
  6. While Configure has unsaved changes, single-model and whole-workspace exports are blocked, with concise feedback to save or discard first. Export does not open Save / Discard / Stay or leave Configure. Saving or discarding through the existing controls never triggers a download or opens the export menu; the user activates Export again. A failed Configure save retains its draft and error feedback, and Export stays blocked while the draft is unsaved.
  7. With a clean Configure form, Export works directly from Configure without leaving that screen. Save / Discard / Stay remains unchanged for other Configure exits.
  8. Mouse and keyboard activation use the same saved-state policy. Opening the two-model export menu does not schedule a later menu opening or download, including from Configure. Exports of saved values from unfinished Modeling or timeseries panels continue to work.

3. Scope

In scope

Simplified-input inline value/provenance edits followed by the ordinary single-model or whole-workspace Export action; Configure export with clean or unsaved configuration; repeated activation after saving or discarding; saved-state export after browser validation failure or server rejection.

Out of scope

Redesigning the shared workspace write policy, autosave, validation, accepted-field restoration, other Configure exits, file formats or server persistence. No new export queue, automatic retry, unsaved-export dialog or UI control.

4. UX / interface

5. Constraints

Stay within the mission and constitution, particularly minimal browser JavaScript. Use the scoped field-save lock from the save-lock replacement and retain accepted-state ownership described in Persistence and Rendering.

This intentionally replaces the original Simplified-input requirement to finish a focused edit before export, resume export after saving, and cancel export for a browser-invalid edit. It also replaces Configure's deferred export with blocking while dirty and a fresh activation after saving or discarding; clean Configure exports no longer leave the screen. The workspace mutation-gate spec uses the same saved-state export policy defined here. The later save-lock replacement disables buttons and Simplified-input fields only during field saves; native links remain usable and other Configure exits keep their existing protection.

6. Open questions

No product decision remains from the kickoff. Requiring another activation after a blocked click, including after resolving a Configure draft, and allowing export of the previous saved state while an inline edit is invalid are accepted tradeoffs. Planning must verify ordinary focus/save ordering and use an existing feedback surface for dirty Configure export blocking.
