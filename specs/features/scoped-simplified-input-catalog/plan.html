REFACTO · Proposed plan · 8 October 2026

Scoped simplified-input catalog

Planning kickoff · Audit and measurements · Changed files

Deliver the empty-settings structural shortcut and four narrow read paths: field refresh, focused timeseries, lazy bookmark controls, and rejected-edit restoration. Keep complete catalogs for workspace discovery, edit panels, Sources rows and writes. This scope is proposed for review; implementation is not authorized.

1 · One catalog, with a requested closure

Paths are relative to e-footprint-interface/. The sole companion-library reference below is marked explicitly. Sketches show proposed changes.

Extend build_catalog() with an optional requested-address set. Retain FieldAddress, FieldDescriptor and FieldCatalog; add no stored metadata or alternate catalog type. The adapter continues to supply can_edit_timeseries(), which inspects the saved builder without initializing its editor.

model_builder/domain/services/simplified_inputs.py Proposed contract sketch

def build_catalog(model_web, *, can_edit_timeseries,
                  requested: set[FieldAddress] | None = None) -> FieldCatalog:
    # None: complete catalog. Empty set: empty catalog.
    # Otherwise: existing requested constructor fields + all dependents.
    ...

For a non-empty request, return exactly the known requested constructor fields and their transitive dependent closure. Preserve each descriptor’s eligibility, reason and controller address. Return dependent lists for controllers in that closure, in the full catalog’s order. Unknown owners, unknown attributes and computed-only inputs remain absent; structural constructor fields remain present with their current ineligibility.

A requested dependent does not pull in its ancestors or siblings. Its descriptor still carries the upstream controller address, which the bookmark reader uses for the included-controller label. A requested controller must pull in every required descendant across owners, whether or not those descendants are selected.

Share discovery and evaluation

  1. Extract conditional-link discovery from the current constructor loop. Scan each owner’s conditional metadata, retaining only dependent attributes present in its constructor signature, excluding self. Resolve each controller through resolve_input_path(). Keep small request-local controller and reverse-dependent dictionaries; full and scoped modes use this same discovery. The companion library’s get_init_signature_params() already caches signatures.
  2. In requested mode, traverse reverse-dependent links with a visited set, starting with known requested constructor addresses. Empty requests return an empty catalog before discovery. Cycles terminate; overlapping requests share one closure.
  3. Evaluate fields in existing model-owner and constructor-parameter order, filtering to the closure in requested mode. Use the existing input_eligibility() once per retained field, and allocate only retained descriptors. In full mode, evaluate every constructor field.
  4. Extract the current ineligibility propagation loop unchanged into one private helper used by both modes. Canonical field order preserves its first failing companion and nested error explanation. Filter returned reverse links to controller keys represented in the scoped fields.

For example, requesting a video API provider includes its model selector and the resolution on every linked video job; requesting one resolution includes only that resolution. An unsupported resolution still makes the requested model/provider ineligible. The existing test_real_cross_owner_chain_includes_every_linked_jobs_resolution() and test_ineligible_required_input_propagates_to_all_controllers() ground these cases.

Let N be objects, F all constructor fields, L conditional links, K retained closure fields, and P constructor parameters traversed on owners represented in the closure. Full work remains O(F + L). Scoped work is O(N + L + P), with K eligibility evaluations and descriptors; it still scans model-wide conditional metadata. Scratch link storage is O(L), scoped descriptor storage O(K). Canonical filtering avoids sorting or a second persistent field-order index. Full mode gains a sparse discovery pass; measure that cost before accepting the refactor.

Owning contract: Forms and relationships → simplified-input catalog.

2 · Save an ordinary structural change

reconcile_simplified_definition() currently builds a catalog before pruning removed owners and applying pending settings. Move catalog construction after those existing operations, which already run after mutation and hooks. Choose an empty FieldCatalog when the resulting definition contains no field entries; otherwise call the existing factory for a full catalog.

model_builder/application/use_cases/simplified_inputs.py Proposed contract sketch

# After existing owner pruning and pending-setting resolution:
has_field_entries = any(definition["fields"].values())
catalog = catalog_factory(model_web) if has_field_entries else FieldCatalog({}, {})
# Continue through the existing submitted-selection calculation and
# UpdateSimplifiedDefinitionUseCase(...).execute(..., replace=True, persist=False).

The condition includes unselected help-only entries and pending entries with false inclusion or empty help: any actual field entry requires the full catalog. Empty owner buckets require no catalog, but still pass through the current shape validation. Do not normalize malformed buckets into empty dictionaries or add a separate validator.

Continue through UpdateSimplifiedDefinitionUseCase.execute() and validate_definition() with the chosen catalog. Thus title/guidance validation, normalized configuration and removed-owner cleanup retain their existing path. persist_structural_change() still invokes ModelWeb.persist_to_cache() once and restores request-local configuration on failure. This shortcut avoids catalog work; it does not skip the final save or model hydration.

Creation still resolves declared nested owners and validates pending settings before the choice. Retained settings still discover current cross-owner links after relinking/hooks. Existing test_creation_resolves_nested_settings_and_saves_model_once(), test_new_dependents_are_completed_after_creation_hooks() and test_structural_relink_completes_current_controller_dependencies() stay on the full path whenever settings exist.

3 · Refresh a field or open its timeseries editor

Extend input_catalog() to forward the optional request. In build_workspace_context(), scope construction only when explicit addresses are supplied and Configure is false. A caller-supplied catalog always wins, including an empty one; never build another catalog merely because the renderer displays fewer fields.

In simplified_timeseries_panel(), construct the address before requesting its catalog, then pass a singleton request. present_edited_input() still reuses the full catalog supplied by the successful write. save_simplified_inputs() and patch_simplified_inputs() also retain full catalogs and existing validation. No write is scoped by the new argument’s default.

4 · Open one Sources bookmark

simplified_input_bookmark() calls bookmark_context() without a catalog. Change only that fallback to request the one address and its dependent closure. When an edit panel, Sources rendering batch or settings-write response supplies a catalog, keep reusing it.

included_requirement() already obtains the included-controller label from the accepted definition and actual owner. It needs the upstream address carried by the descriptor, not an ancestor descriptor. Keep bookmark identity, retained help, controller locks and unavailable-field 404 behavior. No controller-label cache or browser changes are needed.

Full-catalog consumers remain full: FormContextBuilder.build_edition_context(), source_table() and unfiltered build_workspace_context(). If edit-panel scoping is revisited, use the existing FormStrategy.iter_edition_fields() owner–field pairs; do not recreate nested Storage rules.

5 · Restore a rejected edit from accepted state

_rejected_simplified_input() must keep constructing a fresh ModelWeb from the repository after the error. Its call to render_input_fields_oob() already carries recovery addresses, so the presenter now builds their scoped catalog against that fresh model.

Do not reuse the failed request’s graph or catalog. Before acceptance, render the previously stored values; after persistence succeeds but presentation fails, render the newly accepted values and dependents. Preserve 422 versus 500, the modal, OOB replacement addresses and existing panel treatment. test_rejected_inline_edit_restores_fresh_repository_value_and_provenance() and test_late_controller_failure_restores_accepted_dependent() remain the recovery evidence. No new failure-handler retry is proposed.

Each increment retains useful existing behavior. Finish with bounded measurements and documentation. This is sequencing guidance, not an implementation task list.

Bounded performance evidence

The retained audit measured about 18% catalog share in a 5,002-object edit-panel view and roughly 1 ms versus 104 ms in one focused catalog prototype. Those figures justify testing the shared mechanism; they do not estimate speedups for the proposed read endpoints.

Recreate the audit’s real 100-, 1,000- and approximately 5,000-object graphs through normal serialization/hydration. Use warmed alternating runs, GC enabled, 15 repetitions and two independent processes. Compare the pre-change and final full catalogs, a scalar request, a controller with cross-owner dependents, and a broad requested closure. Record object/field/link/closure counts, medians and spread. Time catalog work separately from whole-request hydration/rendering.

Measure at least one actual field/bookmark GET and an ordinary structural save with no settings against the same stored payload. Record catalog calls and final persistence separately; retain the same repository substitution when comparing whole-request baselines. Accept scoped construction only if its savings exceed run-to-run variability on the large sparse cases. Target full-mode median within 10% of baseline; investigate a repeatable larger regression before approval of implementation. Broad closures need semantic equivalence and measured cost, with no promised speedup. Keep timing assertions out of CI and record results in this working set during implementation.

The implementation must also pass the constitutional gates: full Python unit/integration/E2E suites, Jest, one consolidated changelog entry, and publishable dependencies before merge. The current editable dependency and other pre-existing working-tree edits belong to their existing work; preserve them during planning and implementation. No tests or new performance measurements have been run for this proposed implementation.

Documentation and scope decision

Update catalog documentation and structural persistence documentation when the implementation lands. Propose a one-line addition to the existing AGENTS.md simplified-input guidance explaining that narrow reads request a dependent closure while definition/value writes remain complete.

The remaining review decision is whether to deliver the shortcut plus these four readers together or stop after the shortcut. I recommend both: the shortcut is low complexity, and the shared read mechanism serves several already-narrow operations. Edit panels, consumption workspace, Sources-table construction and non-empty writes are deferred because they broaden integration/validation work; the prior edit-panel benchmark alone is not a compelling reason to include them. This plan changes no library API, UI behavior, JSON schema or persistence format.
