Draft plan · kickoff capture · 2026-11-06

AI-assisted bootstrap

Approved specification · Roadmap

The specification was approved on 2026-11-06. This draft preserves design-rich kickoff decisions and remains unapproved. Resume with a fresh spec-plan pass; this draft is not implementation authorization. Paths refer to this interface repository; no companion-library change is currently proposed.

Confirmed scope. Fresh web bootstrap; one Mistral-hosted Flash model; synchronous execution; no overlap monitoring; a small toolbar cleanup; one destructive Start action; unscaled parent-model EcoLogits estimate; temporary summary only, with a reminder to save the prompt. No AI editing or general architecture refactoring.

1. Start a fresh modeling or switch views

Today the toolbar places a single text-changing view button beside the edge toggle. setBaseView() changes its label, while the Simplified-input CSS removes the neighboring toggle from layout. Replace that arrangement with stable Modeling/Simplified inputs choices, positioned independently of context controls. Group Start with AI, Open a file and Reset modeling in the same small actions menu. The current Help, export and comparison capabilities remain available. Add a single prompt entry to the existing example picker; no broader onboarding redesign is planned.

Use the existing side-panel shell for guidance and the report. The startup operation is a POST because it resets saved state. Reuse the behavior of reset_model() and load_system_into_session(), but return an empty Modeling canvas with the AI input panel rather than automatically opening the example picker.

Expose the same start operation through “Start from prompt” beside the existing scratch/file choices in the example picker. Add the presentational entry through build_picker_groups() and the template, rather than treating it as a serialized example or creating a second generation handler. Accepted start renders the empty active canvas and AI input panel with the picker gone; canceled confirmation preserves the picker and modeling. Use the same availability condition as the toolbar.

Check the first-run tour trigger when dismissing the picker: its current guard waits only for the picker to disappear, so the tour must not open over the AI description or summary. Reuse its existing first-run state; do not introduce remembered tour intent or a new onboarding workflow. The Help menu remains the manual replay entry.

The replacement warning precedes this operation. the conditional replacement confirmation currently checks for cards across the document; with resident slots this is not proof that the active modeling is non-empty. Ground the new action's decision in the active modeling, not a parked comparison canvas. Preserve the existing dirty Configure guard in registerWorkspace(); it blocks and the user repeats the action after resolving the draft. Do not add intent replay.

Confirmed behavior differs deliberately from open_import_json_panel(): the import panel opens without replacing state, whereas AI Start clears on confirmed entry. Canceling that warning preserves everything. Closing the AI input panel later does not restore the discarded modeling. Starting AI from an edge modeling is permitted only as this explicit fresh web start; it must not reuse the old edge objects or the PoC's edge-based hiding rule.

Apply the same start and generation operations to either the active reference modeling or the active comparison modeling through the existing workspace repository resolution. Do not hardcode the reference slot as the destination or create a separate comparison-generation path. Confirmation, reset, installation and the resulting canvas/side panel belong to the selected modeling; preserve the other modeling and its saved inputs. The existing comparison workflow then compares the independently created results.

The input side-panel guidance asks for volumes per usage where applicable: separate each usage journey’s visits/occurrences per period, or its users and frequency, instead of applying a single system-wide user total to every journey. Use an example with distinct browsing and photo-upload volumes.

Start is the only AI entry action. There is no summary endpoint, conditional report action or report-invalidation path. The successful response opens the temporary summary; ordinary side-panel replacement discards it.

2. Generate and install one fresh web modeling

Debug current generation baseline

This runs the existing PoC test with a fake provider, not the proposed production flow. Set a breakpoint first if useful. No separate Django server or paid inference is needed.

Replace the mixed handler ai_assistant() with a thin generation view that invokes a small application operation. The operation accepts the description and an injected provider callable/port, parses and validates its answer, and constructs a library System. It does not import a Django view, HTTP request, presenter or concrete repository adapter.

Extract the useful schema and build_system() construction path, the prompt, and catalog resolution into the proposed application package. Keep deterministic catalog selection and per-value reasoning. Reuse the library's constructors/defaults; do not duplicate modeling invariants, route whole-System construction through form-shaped object operations, or refactor unrelated editor policies. Ensure the cached catalog asset follows the extracted resolver. The sandbox runner should consume this same implementation instead of keeping a divergent copy.

Introduce the single Mistral adapter at the application's provider call. It returns raw text plus the minimal usage/latency data needed for cost and impact estimates. Configure the one model server-side, with an explicit timeout and bounded request behavior; no automatic model fallback, clarification round or repair loop. The production SDK must be installed at runtime; remove the multi-provider selector in ai_assistant() and the sandbox-path import trick in the experiment view.

The current one-worker deployment and provider timeout still need compatible bounds; this is configuration, not a prerequisite asynchronous project.

3. Review the temporary summary

On generation success the AI summary side-panel template replaces the description side panel and shows cost, the qualified parent impact estimate and the review order: usage-step durations, usage-pattern volumes, infrastructure. The initial prompt is escaped, collapsed, read-only and copyable. The summary has only the top-right close cross as an explicit dismissal control; omit the shared panel footer/action button and any “Review on the canvas” button. Keep the notice that closing discards the generation details. The separate Results panel stays closed.

Include the notice: “Save your description if you want to keep it. These generation details won’t be available after closing this panel.” There is no summary-reopening action, report store, browser-retained fragment, conversation history, or automatic prompt export.

Keep the prompt and call metrics only in the response context used to render this panel. The generated modeling follows normal persistence. Closing or replacing the panel, including opening an ordinary edit panel, discards the summary without changing the modeling. A reload does not reconstruct it. Use the existing side-panel lifecycle; do not add state retention or replacement/reset invalidation hooks.

4. Close the experiment after production replacement

Remove the AI edit/read-back module and the edit prompt from the delivered tree. Remove the old non-empty-model branch, multi-provider floating UI, edit-only tests and stale active requirements. Keep independent editor regressions such as sequential deletion: they protect the ordinary editor and library integration.

Retain generation cases, replay/evaluation tools and developer-only provider comparisons where still useful; update them to call the extracted generation code. Review the sandbox guide so it describes the remaining tool, not removed edits. Do not preserve a disabled editing implementation or an old-code directory. Git history preserves the experiment; record the final relevant revision before archiving.

At delivery, consolidate the production changelog and update owning architecture/copy documentation. Then use the explicit feature-archive workflow for the PoC, promoting only durable lessons and removing its working set after the release/checks are complete. Do not perform that archive during this specification stage.

The AI assistance roadmap now records the ordered next features: edge bootstrap, then asynchronous provider I/O. Broader AI editing remains uncommitted direction, informed by the existing lifecycle and mutation-policy discussion.
