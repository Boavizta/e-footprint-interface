Implementation plan · validated · 2026-11-09

AI-assisted bootstrap

Approved specification · AI assistance roadmap

Refined against the current PoC and workspace code. The specification was approved on 2026-11-06; the user validated this plan on 2026-11-09. All production changes belong to this interface repository. No companion-library change, schema migration or new persisted AI state is needed.

Scope retained. Fresh web bootstrap for either active modeling; one Mistral-hosted Flash model; synchronous inference; small toolbar cleanup; reset on confirmed entry; qualified, unscaled parent impact estimate; temporary summary only. No spec changes proposed.

Reading order follows user interactions. The delivery sequence separates extraction, lifecycle/UI integration and retirement. Proposed names and sketches below describe the anticipated diff, not existing implementation.

1. Start a fresh modeling or switch views

Choose a view without moving the controls

The current toolbar has one text-changing view button. setBaseView() changes its label, and the Simplified-view rule removes its neighboring edge toggle from layout. Replace the one toggle with two fixed-label buttons, Modeling and Simplified inputs, before the contextual controls; update their pressed/active states in that same function. Explicit actions select a destination rather than inverting the current mode. Selecting the already active view does nothing; entering Simplified inputs still uses the existing saved-view read.

Keep the view pair in a non-shrinking group and the edge control in its own reserved-width wrapper. In Simplified inputs, hide that wrapper’s contents with visibility rather than collapsing its width; continue hiding the canvas scroll arrows. This is the narrow toolbar correction in the approved mockup. Group Start with AI… (Beta), Open a file… and Reset modeling under one Modeling actions menu. Keep Help, export, Results and comparison in their existing roles.

The new buttons carry the workspace-control marker so registerWorkspace() continues intercepting dirty Configure exits. Both Start entries declare the standard button lock, inherited by any descendants; the generation form declares it directly. No queue, second lock or pending-navigation state is introduced. The clean view controls keep the existing per-slot view memory and loadView() side-panel discard behavior.

Confirm before resetting the active modeling

Both toolbar Start with AI… and the new picker card post to the proposed start_ai_bootstrap() in views_ai_bootstrap.py, registered as POST /model_builder/start-ai-bootstrap/. They target the whole builder, #main-content-block, with an inner swap. POST is necessary because accepted entry replaces saved state. Share the same availability check from ai_bootstrap_available(): the new server flag is enabled and a Mistral key is configured. The context processor exposes only that boolean; both POST views return 404 when unavailable. Do not gate entry on whether the current modeling contains edge objects.

Use the existing replacement-confirmation marker. Its delegated htmx:confirm handler currently looks for a card anywhere in the document. Scope that test to the canvas whose slot matches the active-slot attribute; use the resident canvas even while Simplified inputs hides it. This fixes the confirmed empty-active/populated-sibling case for single-model replacement actions. Keep file upload’s existing workspace-file warning text; this feature does not redesign upload confirmation.

The AI warning states that content and unsaved edits are discarded now, that closing or failure leaves an empty modeling, that users should export first if needed, and that the other modeling is preserved. Cancel sends no request, closes no picker/panel and writes nothing. Confirm issues the one Start POST. Like reset/example loading, this whole-builder action uses its own destructive warning, so do not add it to PANEL_DISCARDING_PATHS and stack an ordinary side-panel warning. Dirty Configure still blocks before the request and requires the user to repeat Start after Save/Discard.

In start_ai_bootstrap(), resolve the active repository through SessionWorkspaceRepository, set its request-local UI settings to an empty definition, and call load_system_into_session() with the scratch baseline and the workspace. Assigning empty UI settings is necessary: save_data() merges an already loaded settings dictionary into the new payload. Do not leave selected inputs or Sankey settings from the discarded graph. Do not clear the slot’s backend first; the existing import/size checks run before publishing the replacement.

2. Generate and install one fresh web modeling

Debug reproduction

This is the current PoC baseline, before the proposed refactor. It uses a fake provider and the local Django test client; no separate server or paid inference. The review-link extension launches Poetry pytest with --runxfail. Copyable command: poetry run pytest --runxfail tests/integration/test_ai_assistant.py::test_generate_on_empty_model_loads_the_answer_and_shows_the_feedback.

Call a shared application operation

Rename views_ai_assistant.py to views_ai_bootstrap.py. Replace ai_assistant() with the two thin POST views. Generation reads the active saved payload and uses is_empty_model() before inference. If it now has content, return a visible “Start with AI again to replace this modeling” message without calling the provider or changing it. This enforces the operation’s fresh-only contract; do not silently reset here or fall into the removed editing branch.

The first application call is generate(description, complete) in the proposed service module. The view passes complete_mistral(system_prompt, description) as a callable. The service reads its packaged system prompt, calls the provider once, and passes the returned text to build_answer(text), which runs the extracted parsing, schema validation and builders. Both functions are Django-free; neither writes a repository. A callable is sufficient here: no provider registry, abstract class hierarchy or separate repository port is required.

Make one bounded Mistral request

At the injected provider call, complete_mistral() adapts the useful part of _mistral(). Keep JSON-object output, low reasoning effort, a 16,000-token output cap and text-chunk extraction. The server-owned model is fixed to zai-glm-5-3-flash; no submitted model name is accepted. Retain only text and usage/latency/stop metadata needed by the pipeline. Drop the current approximate reasoning-token split and request-parameter capture from production.

Local inspection on 2026-11-09: installed Mistral SDK 3.5.0 supports per-call timeout and explicit retry disabling, but defaults to a 300,000 ms request timeout. Set timeout_ms=45,000 and retries=None explicitly. Map provider failures to a small content-free bootstrap error, with no request/response body in the exception text returned to the UI or logged. Do not enable SDK debug/body logging. Reject a truncated/non-success completion before building; it returns the description panel for an explicit retry.

The chosen provider timeout is below Gunicorn’s 120-second timeout and nginx’s 240-second proxy timeout, leaving room for ordinary build/import/render work without changing worker configuration. It bounds the SDK request; it is not a new end-to-end deadline for all model computation. Synchronous worker contention remains the accepted first-release tradeoff. No async worker, overlap experiment or background job is a prerequisite.

Move Mistral from development dependencies into runtime dependencies and update the lock. Keep Anthropic/OpenAI SDKs development-only for the retained comparison CLI. Replace the experiment’s AI_ASSISTANT_ENABLED setting with AI_BOOTSTRAP_ENABLED (default false), plus a server-side Mistral key. Document these deployment inputs; changing deployment configuration or making a paid call is outside this planning run.

Prepare, validate and save once

load_system_into_session() currently upgrades, imports/recomputes, distinctifies, wraps and persists in one helper. Extract the pre-persistence body as proposed prepare_system_for_session(repository, raw_system_data, workspace=None), returning the prepared wrapper. The existing load helper calls it then persists, preserving all current callers. Generation calls preparation, then the existing SystemValidationService.validate_for_computation(), then persists. This separates the only new completeness gate from the scratch/reset path, which intentionally allows an empty graph.

Serialize the newly built System with the existing library inputs-only format at the view boundary. Preparation still uses SystemImportService.import_system() for computation and serialized payload checking and distinctify_against_siblings() for canvas identity. The existing completeness check rejects, for example, a schema-valid answer with no usage patterns or a used journey with no steps. Keep those rules in their current owner. Do not build a second rollback graph or persist during construction.

Explicit empty UI settings prevent carrying the scratch model’s authored configuration into the generated modeling. persist_to_cache() already produces canonical Redis and inputs-only recovery payloads; save_data() already checks the combined workspace size before writes. Keep those boundaries. They do not provide a new cross-backend transaction guarantee; ordinary storage failures remain ordinary repository failures.

Expected generation failures return a rendered HTML fragment with visible feedback and status 200, following the existing validation-panel convention; no client error masking or automatic retry. Unexpected infrastructure failures use ordinary error handling. A failure to compute the AI call’s impact is separate from computing the generated modeling and must not take this rejection path.

Estimate this call’s cost and impact without retaining its contents

Replace call_metrics() with estimate_call(completion), called after a valid modeling has been installed. Local check on 2026-11-09 confirms EcoLogits 0.11.3 resolves provider mistralai, model zai-glm-5-3, and has no Flash entry. Call that parent entry explicitly; do not use the nearest-catalog-name resolver for the inference estimate. Its role for APIs inside the generated modeling is unchanged.

Use the provider’s reported completion-token total and elapsed seconds in EcoLogits. Keep its scalar or min/max GWP value in kg until rendering, preserve the interval where present, and format with the library’s existing unit/precision convention. A local synthetic input of 1,000 completion tokens and 10 seconds returned a scalar ~0.000143 kg CO2-eq; this was an offline estimator check, not a measured Flash call. Estimate errors, absent usage or non-finite output yield “Impact estimate unavailable”, never zero, and do not reject the generated modeling.
