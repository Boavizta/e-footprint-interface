AI-assisted bootstrap

Status: specification — approved · 2026-11-06 · Interface-owned

Validated implementation plan · AI assistance roadmap

1. Problem and audience

Creating a first modeling requires translating a service description into usage journeys, volumes and infrastructure before users understand the editor. The PoC made this translation useful enough to pursue a production beta. The primary audience is a product person who knows their service but has little modeling expertise.

The first release generates a starting web modeling, then hands refinement to the normal editor. It deliberately removes AI editing: preserving an existing graph, shared relationships and hand-edited values adds substantially more complexity than creating a fresh one. Edge bootstrap comes next, then asynchronous provider I/O.

Current usage is low according to the maintainer; frequency and broader user benefit have not been quantified. The maintainer accepts synchronous waits, typically observed around 5–15 seconds, and possible delays to other visitors. Overlap monitoring and concurrency experiments are explicitly excluded. Simplicity is a maintenance choice, not evidence of an environmental saving.

Keep one description field and existing manual review controls. The small toolbar change fixes shifting view controls and groups starting actions; a broader toolbar or workspace redesign is deferred.

2. Success criteria

  1. Users can find “Start with AI…” in the modeling actions menu and “Start from prompt” alongside scratch and file starting options on the Examples page, with a visible Beta label. Both enter the same bootstrap flow for the active modeling. Modeling and Simplified inputs remain in stable positions when the view changes.
  2. For a non-empty active modeling, entry warns that its content and unsaved edits will be discarded immediately. Cancel changes nothing. Confirm clears that modeling, selects Modeling, and opens the input panel. The other modeling of a comparison is preserved. Empty modelings need no replacement confirmation.
  3. AI bootstrap works independently for the reference modeling and the comparison modeling. Selecting either modeling makes it the target of “Start with AI…”. Confirmation, reset and generation affect only that active modeling; the other modeling and its inputs remain unchanged. Either side may be AI-generated, manually created or imported.
  4. The input panel helps users describe usages, volumes per usage journey where applicable, and infrastructure. It explains assumptions and required review, and identifies the model, hosting provider, indicative cost/impact and application logging policy.
  5. One submission creates a fresh, valid web modeling with explained AI assumptions and applicable defaults. It fills the canvas and opens the AI generation summary in the side panel. The Results panel stays closed. It does not update an existing modeling through AI.
  6. The AI summary side panel gives the request-specific estimated API cost and the unscaled EcoLogits estimate for the parent model, with uncertainty and proxy disclosure. It guides review in this order: time per usage journey step, usage-pattern volumes, infrastructure.
  7. The result contains the initial prompt in a collapsed, read-only, copyable section and advises users to save it themselves before closing the panel. Its only explicit dismissal control is the close cross in the top-right corner, beside a clear notice that the generation details will be lost. It offers no “Review on the canvas” button, continuation, editing prompt, regeneration button or summary-reopening action.
  8. The summary is shown only in the successful generation response. Closing or replacing the side panel, or reloading the page, discards it without changing the generated modeling. The prompt and summary are not saved for later access or included in modeling exports.
  9. During inference, existing request locking prevents duplicate submission. On provider, validation or construction failure, no partial generated modeling is saved; the input panel retains the description for an explicit retry. Because entry already reset the modeling, failure or closing the input panel leaves it empty.
  10. Prompts, raw AI responses and generated modeling contents are absent from application AI logs, including failure paths. Latency and cost metadata may be logged. The disclosure does not promise that Mistral performs no processing or retention.
  11. The production beta replaces the PoC UI and AI edit path. Useful generation evaluation tooling remains; removed experiment code remains recoverable through Git. PoC close-out happens after delivery and required checks, not merely on specification approval.

3. Scope

In scope
  • Fresh web bootstrap: usage patterns, journeys and steps, server/GenAI workloads and their supported infrastructure. The result remains fully editable with existing controls.
  • The same bootstrap flow is available for either active modeling in a comparison, independently of how the other modeling was created. Use the existing modeling selection and comparison workflow.
  • A guided input side panel and an AI summary side panel, using the same existing side-panel surface. This is separate from the Results panel.
  • One bootstrap operation, reached through “Start with AI…” in the toolbar or “Start from prompt” in the example picker. Both use the same active-model confirmation/reset and input panel. A temporary summary appears after generation; users save their own prompt if they want to keep it.
  • A narrow toolbar cleanup: stable Modeling/Simplified inputs view selection, with starting/reset/import actions grouped rather than adding another permanent toolbar button. Keep the edge toggle's meaning and the existing help, export and comparison capabilities.
  • One configured model hosted by Mistral, beta disclosure, useful prompt guidance, cost and impact disclosure, manual review instructions, feedback and contribution invitation.
  • Synchronous inference, ordinary loading/error feedback, bounded provider waiting, and explicit retries by the user.
  • Production generation extraction and retirement of the experimental editing experience and prompt/response logging.
Out of scope
  • Edge or mixed-model bootstrap: roadmap follow-up 1. An existing edge modeling may be discarded through the same explicit start-over confirmation; this does not extend generation to edge.
  • Asynchronous I/O, background jobs, streaming, progress prediction, overlap monitoring and concurrency experiments: follow-up 2.
  • AI modifications of an existing modeling, conversations, provider/model selection, classifier routing, automated questions, web research and automatic repair/retry loops.
  • A wider toolbar/navigation redesign, onboarding changes beyond the prompt entry and its integration, or the broad Clean Architecture refactoring.
  • Summary reopening or retention, conversation/report history, prompt export/import, and restoring the discarded modeling after a confirmed restart.

Scope review: these are five connected interactions—entry/reset, description, generation/failure, immediate summary review, and view switching—on the existing canvas and side panel. The user approved the small toolbar cleanup and deferred the broader redesign. The later simplification removes summary reopening and all report retention; users save their own prompt.

5. Constraints

  
    
    
  • Respect the constitution and mission: library modeling truth, existing persistence/recovery rules, HTMX-first interactions, lean implementation and honest environmental claims.
    • 
    
  • Use the existing side panel, request lock and normal manual editing. A dirty Simplified-input configuration blocks navigation through its existing exit guard; after resolving it, users repeat the desired action. No new remembered-intent mechanism is required.
    • 
    
  • Production inference uses zai-glm-5-3-flash on Mistral. Waiting is synchronous in this release. Keep bounded provider waiting and ordinary failure handling; tolerate contention without adding overlap monitoring.
    • 
    
  • Cost is a request-specific estimate using reported token usage and dated provider prices, not an invoice. Impact is an unscaled EcoLogits estimate for zai-glm-5-3, identified as the parent-model reference; show uncertainty where available. Failure to estimate impact must not discard a valid generated modeling or display zero as a substitute.
    • 
    
  • The prompt and generation metrics are rendered in the successful response only; no report is saved server-side or retained separately in the browser. Users save their own description if needed. The generated modeling is persisted normally. No promises about provider retention/training are inferred from the application's logging choice.
    • 
    
  • Keep the PoC until production replacement and required verification are complete. Git history is the archive; do not retain disabled AI edit code or create an old-code directory.
    •
