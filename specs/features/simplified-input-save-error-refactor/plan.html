Plan · implemented · 2026-10-07

Simplified input save errors

No new spec: this interface-only refactor follows the Simplified-input review. It deliberately changes two existing behaviors: a rejected inline autosave restores the accepted field instead of retaining a retryable draft, and a rejected timeseries Save closes its editor instead of keeping the draft open. The original spec and Decision 08 have been synchronized with this refactor. No library change was needed.

Changed files · Rendering architecture · Current error modal

1. Follow the interactions through the code

Implemented behavior and its review path. Paths start at e-footprint-interface/. Changed files belong to that repository; library references link to their own repository.

1.1 · A request returns an error modal

Files exception_handling.py · modal_utils.js · model_builder_main.js

Before this refactor, render_exception_modal() returned HTTP 200. The shared mutation guard and bookmark handler therefore searched HX-Trigger-After-Settle for openModalDialog to decide that the save failed. Keep that trigger solely to open the modal; use the HTTP status for the save outcome.

Give render_exception_modal() a 500 default and let a caller request 422 only after it identifies a validation rejection. This applies to known parsing or domain validation in the three Simplified-input save POSTs (inline edit, Configure and bookmark) and in add_object()/edit_object(); the library's typed WeeklyPatternValidationError is one concrete side-panel example. The decorator remains the catch-all 500 path. A POST method or generic ValueError alone does not establish that an error is a known validation failure. Keep the existing OOB modal markup, HX-Reswap: none, and preserve_panels/preserve_workspace behavior. No custom status code or new payload format is needed.

Explicit Simplified-input validation raises InputValidationError so the save views can return 422 without classifying a persistence ValueError as invalid user input.

model_builder/adapters/views/exception_handling.pyImplemented response contract

caller identifies a validation rejection → HTTP 422
unclassified or unexpected exception → HTTP 500
both → HX-Reswap: none + existing OOB modal
HX-Trigger-After-Settle opens the modal, not a save-outcome signal

The bundled HTMX 2.0.6 does not swap 4xx/5xx bodies by default. In modal_utils.js, its existing htmx:beforeSwap listener permits the body only when the response is an HTTP error carrying HX-Reswap: none. Set shouldSwap true and leave isError true. HTMX then processes the modal's OOB fragment without replacing the main target. The listener loads before the guard's beforeSwap listener, so the guard sees the final swap decision and waits for settlement.

model_builder_main.js can set mutation success from event.detail.successful alone. This also fixes the same false-success signal for ordinary Modeling and middleware error modals without changing their form/panel behavior. Keep the shared in-flight lock and its settlement logic.

1.2 · An inline value or provenance edit is rejected

Files views_simplified_inputs.py · presenters/simplified_inputs.py · simplified_inputs.js · editor.html

On a successful edit_simplified_input(), present_edited_input() already sends affected field.html fragments OOB, plus total/results updates. Keep that path. Its exception path now returns only the modal and leaves the submitted control in the DOM, which created failedEdits, data-save-failed, Retry and Discard and the navigation guards.

After initial model hydration and catalog construction succeed, build targeted OOB field fragments for a rejected save from a fresh ModelWeb over the active repository, then include it with the error modal. ModelingUpdate rolls back its own rejected recomputations, but the endpoint also catches later failures: persist_to_cache() can reject a successfully updated request-local model before storing it, for example at the payload-size limit. Metadata-only edits can mutate that request-local model without ModelingUpdate. Conversely, response rendering can fail after persistence succeeds. The repository therefore determines which value the browser should show in every case. Before use-case success, restore only the submitted address; if presentation fails after execution, restore every address in output.changed_fields, including persisted conditional dependents. Reuse build_workspace_context(..., addresses=addresses) and field.html; do not re-render the full workspace or recompute totals on an error.

model_builder/adapters/views/views_simplified_inputs.pyImplemented failure sequence

edit_simplified_input() fails after initial model/catalog are usable
→ 422 for an identified validation rejection, otherwise 500
→ read the active repository again
→ render accepted field.html fragments for the affected addresses as OOB + existing error modal
→ keep the previous quick total and Results content
initial model/catalog failure → 500 OOB modal only, because no accepted field is available

After the OOB replacement, workspace-mutation:finished reports Not saved on the new field without treating its control as a pending draft. Remove failedEdits, markEditFailed(), retry clicks and the two buttons from editor.html. Keep savedEdits for unchanged-input suppression and provenance-key omission. Native reportValidity() still prevents an invalid form from being sent; it must also stop a focused-field export from continuing when no request was issued.

1.3 · The user leaves, replaces or exports after a failed edit

Files simplified_inputs.js · model_builder_main.js · model_comparison.js

The accepted field is back in the resident view after an HTTP error, so there is no failed draft to protect during Modeling/Configure entry, model switching, shell replacement, reset or export. Remove failedExportForm(), requireEditRecovery(), failed-edit click and htmx:confirm guards, and the discardsSimplifiedEdits branches in the main confirmation and comparison confirmation. Model-removal confirmation and ordinary side-panel unsaved-change protection remain.

Keep completeFocusedEditForExport() and pendingExport: activating Download while a focused field has changed still sends that field first. Continue the download only after a successful save. On a non-2xx response, the download is cancelled for that click and the OOB field shows the accepted value; another click can export it without Retry/Discard. A browser validation failure also cancels that click. The existing workspace mutation lock still prevents navigation or export during an in-flight request.

A connection abort or timeout has no OOB response: the submitted inline control remains visible as Not saved and can be retried, while a pending focused export is cancelled. Later navigation may discard that visible draft; the accepted-field restoration above applies to HTTP error responses.

1.4 · Configure, timeseries or bookmark saves fail

Files views_simplified_inputs.py · simplified_inputs.js · timeseries_panel.html

save_simplified_inputs() keeps its explicit Configure draft and Save/Discard/Stay exit guard on a non-2xx response. On a failed timeseries Save, the selected field receives its accepted-value OOB fragment, then the workspace-mutation:finished handler closes and empties the side panel as it already does on success. This matches ordinary Modeling error cleanup and discards the unsaved timeseries draft; there is no panel value to synchronize. Remove data-timeseries-save-status and the extra rule that blocked timeseries Save because a separate inline provenance autosave had previously failed.

patch_simplified_inputs() still returns JSON on success and the modal on failure. The bookmark handler uses event.detail.successful rather than searching the modal trigger header; its current local help draft and Undo behavior remain. These explicit drafts are separate from the removed failed-inline-edit state.

3. Review points

Behavioral adjustment: the original Simplified-input spec had promised that a rejected inline edit stayed visible for correction, while its timeseries clause kept the editor open after a rejected Save. Run A restores accepted fields after an inline rejection and closes the timeseries editor after a rejected Save, matching Modeling. The original spec now reflects that behavior; this refactor did not create a new spec.html.
