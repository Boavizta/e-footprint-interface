Task 16 · Group-member deletion confirmation recognizes hook-managed memberships

CONFIRMEDPLANNED · RUN Be-footprint-interfacestandard diagnostic

Symptom
A custom edge device held only by a group, or an otherwise unreferenced subgroup, cannot be deleted through the normal confirmation flow. Both return can_delete=False naming “Parent group”, although their deletion hook supports removing those memberships. Found during Run A's Task 11 review; reproduced on its baseline and reviewed implementation. Run A did not introduce this refusal.
Root cause

Permit ordinary group membership through confirmation without adding it to generic execution removal targets or unlinking it twice. Limit the exemption to actual parent-group membership relationships; do not exempt every dict reference to a group member. Preserve Task 8's early internal-parent guards and Task 11's independent reference blockers. Leave the existing execution hook and cascade unchanged unless an allowed-deletion regression demonstrates a defect.

Add a grouped device also referenced by a recurrent need: confirmation must name that independent holder, and request-local and saved state must stay unchanged; never execute a refused deletion. In test_views_deletion.py, verify grouped device/subgroup confirmation offers “Yes, delete”, while the independently referenced device does not. Reuse existing fixtures and edge-group deletion suites.

@property
def _containment_path(self):
    path = f"{self.class_as_simple_str}-{self._modeling_obj.id}"
    if self.parent_container is not None:
        path += f"_in_{self.parent_container._containment_path}"
    return path

@property
def web_id(self):
    return f"{self._system_web_id_prefix}{self._containment_path}"
