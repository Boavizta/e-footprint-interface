### Answer to "should `prepare_input_changes` raise on unknown attributes?"

No. Real form payloads carry non-constructor keys on purpose: `_parsed_Storage` reaches `edit_with_cascade_cleanup` with the
same `form_data` (`model_builder/domain/entities/web_core/hardware/server_web.py:53-63`,
`model_builder/application/use_cases/edit_object.py:93-100`), as do helper fields such as `service_or_external_api`.
The skip at `model_builder/domain/object_factory.py:179-181` is load-bearing. The silent no-op is better caught where intent
is known: S1's post-delete check.

## Looks suspicious but is sound

- **One `attr_name_in_list_container` (and dict) returned for several containers, last one wins**
  (`modeling_object_web.py:383-409`, consumed at `delete_object.py:186-188`). A signature scan of every modeling class
  (`sig_scan.py`) shows that each child class is held under one attribute name only. For example, `Job` is under `jobs` in
  both `UsageJourneyStep` and `RecurrentServerNeed`. The dict side is pinned by the registry uniqueness test
  (`specs/architecture/forms-and-relationships.html`, dict relationships). The list side has no such pin. S3's sweep
  would cover it.
- **`EdgeGroupMemberMixin.pre_delete` mutates parent dicts with `del` outside a `ModelingUpdate`**
  (`model_builder/domain/entities/web_core/hardware/edge/edge_group_member_mixin.py:30-36`). The library's `__delitem__`
  is transactional (`e-footprint/efootprint/abstract_modeling_classes/explainable_object_dict.py:235-250`), and the
  weighted dict refuses removal of the final member (`:470-473`).
- **`JobWeb.links_to` returns one bare root `web_id` instead of `|id|id`**
  (`model_builder/domain/entities/web_core/usage/job_web.py:32-38`). The client splits on `|` and drops empty parts
  (`theme/static/scripts/leaderline_utils.js:111-116`). Servers, external APIs and services render with root ids:
  services are wrapped from the library's `installed_services` with no list container
  (`model_builder/templates/model_builder/object_cards/server_card.html:43-44`).
- **`EditService` compares accordion children through the first mirrored card only** (`edit_service.py:57-62`). An edit
  changes the object's own attributes, not its containers, so the set of mirrors is stable across the edit.
- **`ModelingObjectWeb.self_delete` forward cascade** (`modeling_object_web.py:574-589`). `mod_obj_attributes` is wrapped
  by `__getattr__`, so the cascade recurses through web `self_delete` (and `ServerWeb.self_delete`'s services). The
  library's `modeling_obj_containers` already excludes detached wrappers (`e-footprint/efootprint/abstract_modeling_classes/modeling_object.py:459-465`),
  which is consistent with Task 4's filter.
- **`source_table_row_editor_context` builds `{attr}-in-{object_id}` by hand**
  (`model_builder/adapters/views/source_table_row_editor_context.py:89-90`). This is deliberate: it serves a JSON-only path
  that avoids hydrating a `ModelWeb`, and it matches the library's non-dict id format
  (`e-footprint/efootprint/abstract_modeling_classes/object_linked_to_modeling_obj.py:105-106`). It is coupled to that
  format, but only for input attributes, which are never dict entries.
- **`check_can_delete` runs a full preview deletion** (`delete_object.py:135-138`), but only when simplified inputs are
  selected. It operates on a fresh `ModelWeb` copy and never persists.
- **The calculated-attribute section ids `collapseCalculatedAttributes{class}`** (`calculated_attributes_section.html:6,11`)
  are distinct in every multi-section panel, because the sections are of different classes (Task 10, diagnostic §6).
