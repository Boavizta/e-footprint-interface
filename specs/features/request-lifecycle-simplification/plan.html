1.1 · Platform: one completion signal

Files theme/templates/base.html · simplified_inputs/editor.html · model_builder_main.js · specs/conventions.md · specs/architecture/rendering.html · specs/testing.md

Settle timing. Verified in the vendored htmx.min.js (2.0.6): defaultSettleDelay is 20 ms, and the swap routine runs its settle step inline when the delay is zero. The response handler then releases hx-disabled-elt and indicator classes, fires htmx:afterRequest on the issuing element, and resolves the htmx.ajax promise last. So with the delay at zero the order inside one response is beforeSwap, afterSwap, afterSettle (including HX-Trigger-After-Settle events and out-of-band fragments), lock release, afterRequest, promise. No project SCSS uses the htmx-settling or htmx-added classes the delay exists to animate. HTMX reads the meta tag once at ready time.

theme/templates/base.html Proposed, in <head> next to the HTMX script tag on line 14

<meta name="htmx-config" content='{"defaultSettleDelay": 0}'>

Lock selector. HTMX resolves hx-disabled-elt with querySelectorAll, splits the value only on top-level commas, disables each match and reference-counts overlapping requests before releasing. The selector on editor.html line 6 skips controls that are already disabled, so HTMX never re-enables a prerequisite-disabled control such as the Compare tab, and the snapshot-and-restore block at model_builder_main.js line 361 is removed with its two listeners. Because that block protected every request, not only field saves, every other hx-disabled-elt="button" declaration becomes hx-disabled-elt="button:not(:disabled)" (PLAN-UPDATE-09); the "this" declarations are unchanged.

simplified_inputs/editor.html Proposed lock selector

hx-disabled-elt="button:not(:disabled), [data-simplified-workspace] input:not(:disabled),
                [data-simplified-workspace] select:not(:disabled), [data-simplified-workspace] textarea:not(:disabled)"

Accepted edge (decision 4): a control already locked by another request, for example the timeseries preview in timeseries_input.html, is skipped and therefore released when that request ends, a moment before the field save finishes. A selector that distinguishes HTMX's own disabling from prerequisites exists but nobody can read it; the edge is rare and harmless.

Affects: Task 1.

Convention. The JavaScript bullet at conventions.md line 26 loses "listener order is part of mutation settlement" and the field_edits.js module, and a new bullet follows it:

[PLAN-UPDATE-06] — ACCEPTED · convention (decided 2026-10-19)

The server is the source of truth; its failures are visible, not softened. Feature JavaScript does not anticipate server errors, slow responses or request races, and does not keep client copies of server-owned state such as saved values, membership or locks. The rendered fragment is the state. A 4xx/5xx response is presented the way the server renders it (today the error modal); a 500 that renders nothing is left visible as an empty or stale target so it gets reported and fixed. HTMX settles synchronously in this project, so htmx:afterRequest on an element means its DOM result is final; nothing observes swap or settle events to sequence its own request. Do not add client state, listeners or fallbacks whose only purpose is to hide a hypothetical failure or to order concurrent requests. When one HTMX attribute expresses the need (hx-trigger, hx-sync, hx-disabled-elt, hx-indicator, hx-vals, hx-on), use it; otherwise accept the edge. Shaping a payload in htmx:configRequest is allowed only where markup cannot express it (nameless controls inside another form). Global re-initialisation hooks on htmx:afterSettle that make any swapped fragment work (tooltips, charts, leader lines, layout) remain allowed; they hold no request state. The exceptions are data-loss cases the mission names as worth protecting, decided in the spec, never added defensively in code.

Why: every mechanism this feature removes, and several the kickoff draft would have kept, exists to soften a failure or a race rather than to deliver a behaviour. The rule is the consequence of constitution §1.4 and of the server being the source of truth; writing it down stops the pattern from returning. A one-sentence amendment to §1.4 making it immutable is listed as a follow-up under decision 10, through update-constitution in its own commit, once this implementation has exercised the text.

The architecture pages reference that bullet rather than restate it: "Results close safely", "Scoped field-save disabling" and "Independent actions" are rewritten around synchronous settle and server-rendered status, the repair-notice paragraph names the fragment instead of the settle event, and the bundle-order sentence stops claiming that order is part of settlement. testing.md notes that settling classes never persist, so click_and_wait_for_htmx() and wait_for_htmx_idle() wait on the request class alone, and tells test authors to assert rendered outcomes rather than dispatch synthetic lifecycle sequences. Unchanged consumers: the loading bar, the modal htmx:beforeSwap handler that lets 4xx/5xx responses swap their out-of-band content, the accordion-state preservation at model_builder_main.js line 353, and every widget re-initialisation hook on htmx:afterSettle, which now runs inside the swap call before the lock is released.

1.4 · Saved-view reads and Configure exits

Files workspace.js · model_builder_main.html · specs/mission.md · specs/architecture/workspace.html

Reads. loadView() registers five listeners per call to tie the continuation to its own XHR, abort on competing navigation and refuse a swap when the active slot changed, and switches to the Simplified view only once the response has settled. It becomes three statements: close the side panel, switch the view, send the read. The view switches when the user asks for it, not when the server answers (PLAN-UPDATE-08), so there is no completion callback at all; HTMX swaps the response into the slot whenever it arrives.

scripts/simplified_inputs/workspace.js Proposed replacement for loadView

function loadView(configure) {
    const target = targetForActiveModel();
    if (!target) return;
    window.runAfterSidePanelDiscardConfirmation(() => {
        window.closeAndEmptySidePanel();
        setBaseView("simplified");
        window.htmx.ajax("GET", `/model_builder/simplified-inputs/${configure ? "?configure=1" : ""}`,
            { source: target, target, swap: "innerHTML" });
    });
}

The slot target in model_builder_main.html declares hx-sync="this:replace". hx-sync is HTMX's rule for a request issued while an earlier one from the same element is still running; replace aborts the earlier one and sends the new one, so the last read wins. The source option makes the slot the issuing element and HTMX reads hx-sync there at request time. This attribute stays because the slot now shows its previous content while a read runs: without it, a user who enters Simplified inputs and clicks Configure before the entry read lands would see the entry response wipe the Configure screen they just opened.

View memory. Each slot carries the view the user last chose for that model as a data-view attribute (PLAN-UPDATE-12). The server renders it from the JSON-opening default in views.py (simplified only when the workspace is rendered with it, otherwise modeling) on the slot in model_builder_main.html, replacing data-opening-default. setBaseView() writes the chosen mode onto the active slot, and initialize() applies the active slot's data-view. A model switch only reveals another slot, so each model gets its own view back. A full builder re-render (Duplicate, Start blank, Import, Remove) brings fresh slots with the server's default, so nothing needs re-fetching. The viewBySystemId map, the opening-default copy at workspace.js and the empty-slot re-read at workspace.js go. A Simplified slot without content then only means a read in flight, which lands, or a read that failed, which stays visibly empty (PLAN-UPDATE-06).

3. Decisions

  1. Results close wait — decided 2026-10-19: remove the wait, make the chevron a button. Field and side-panel saves already disable every button; converting the chevron puts the last clickable close path under that lock. The swipe gesture remains as an accepted mobile edge case. See 1.5.
  2. Failed help draft — decided 2026-10-19: accept the overwrite. Preserving the draft would need a dirty check inside the swap, which is the kind of coordination this feature removes, and the exception modal has already reported the failure. See 1.3.
  3. Scope of the convention — decided 2026-10-19: left to the follow-up. Older modules listed as out of scope in the spec keep their patterns until touched; the server-rendered-state follow-up note carries the survey and applies the convention to them.
  4. Lock selector — decided 2026-10-19: plain :not(:disabled). The variant that distinguishes HTMX's own disabling from prerequisites is unreadable; the overlap edge is accepted. See 1.1.
  5. Bookmark Undo — decided 2026-10-19: removed. Re-clicking the toggle reverts the change; see PLAN-UPDATE-01 in 1.3.
  6. Bookmark fragments need the mounted-instance list — decided 2026-10-19: the browser sends the ids. Rejected: emitting fragments blindly for both suffixes (HTMX logs a console error for each missing target) and making every open bookmark re-fetch its controls on a body trigger (one request per visible bookmark per save). The ids are view state the server cannot know, the controls are nameless by rule, and the response stays pure HTML. See 1.3.
  7. Results close aborts nothing — decided 2026-10-19. A late Sankey response into a detached node may log one warning; that is a symptom to see, not a case to hide. See 1.5.
  8. Exit resume — decided 2026-10-19: removed. Guards block and the user repeats the action; see PLAN-UPDATE-05 in 1.4 and the mission rule.
  9. Provenance trimming removed — decided 2026-10-19: accepted. Relies on the documented patch semantics of _apply_metadata(), with the view test row above as the regression guard. See 1.2.
  10. Constitution §1.4 amendment — follow-up, not part of this feature. One sentence making "server failures are visible, not softened" immutable, through update-constitution in its own commit after this implementation has exercised the convention text of PLAN-UPDATE-06.

Parked, not a prerequisite: an uncaught exception on an HTMX request is invisible in the browser today; the simplified_inputs() read view is one such case. Visibility must come from the server, so the fix is the backlog item htmx-aware-server-error-handler: an HTMX-aware handler500 returning the exception modal, after which the bare exception-modal decorator can be retired.
