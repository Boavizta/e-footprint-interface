1.1 · Press Open in "Open a file"

Files views.py · import_model.html · model_builder_main.js

Today. The toolbar button (upload_download_reboot_model_tooltips.html) and the picker's upload card (template_picker.html) both GET open_import_json_panel(). The panel's #sidePanelForm POSTs straight to upload_json(), which replaces the active slot or restores both. No confirmation step exists.

Guard reused as is. The body-level htmx:confirm listener in model_builder_main.js already serves Reset (toolbar) and example loading (picker). It finds the closest [data-confirm-when-model-not-empty], does nothing when no .model-builder-card exists, and otherwise prompts with the attribute's text before calling issueRequest(true). The form is the requesting element, so evt.target.closest() matches it. In a comparison, both slot canvases are in the DOM (the inactive one is hidden with d-none, see model_builder_main.html), so the existing card check already means "any modeling holds content". No JS logic changes. Only the comment above the listener gains "Open a file" in its list of guarded actions.

model_builder/adapters/views/views.py Implemented in open_import_json_panel(), abridged

def open_import_json_panel(request):
    is_comparison = len(SessionWorkspaceRepository(request.session).list_slots()) > 1
    replace_confirmation = (
        "This will replace the active modeling, or both modelings if the file holds a comparison. Continue?"
        if is_comparison else "This will replace your current modeling. Continue?")
    return render(request, "model_builder/side_panels/import_model.html", context={
        "header_name": "Open a file", "save_button_label": "Open",
        "replace_confirmation": replace_confirmation})

No interaction with the side-panel guards. The unsaved-changes htmx:beforeRequest guard only applies to #sidePanel-targeted requests, and the form targets #main-content-block. The navigation guard's PANEL_DISCARDING_PATHS does not list upload-json. So one click shows at most one dialog. On Cancel, htmx:confirm fires before htmx applies hx-disabled-elt, so the Open button stays enabled and the chosen file stays in the input. "Import a modeling to compare" uses a separate panel (add_model_import.html) and is not affected.

1.2 · Existing E2E callers of the import helper

Files model_builder_page.py · test_toolbar.py · test_workspace_file.py

Playwright dismisses dialogs by default. Over a non-empty modeling, the submit in import_json_file() would be cancelled and its expect_response("upload-json") would time out. The helper is used by seven test files, including the download/upload round trips in test_card_order_persistence.py, test_source_metadata.py and test_weekly_pattern_builder.py. Change the helper once: register a dialog handler that records each message and accepts it, remove it after the response, and return the messages. Callers stay unchanged, and no handler is left behind to accept an unrelated dialog later in the test.

tests/e2e/pages/model_builder_page.py Implemented, abridged

def import_json_file(self, file_path: str) -> list[str]:
    """Import a JSON model file, accepting the replace confirmation when the model has content.
    ...
    """
    ...
    dialog_messages = []

    def accept_dialog(dialog):
        dialog_messages.append(dialog.message)
        dialog.accept()

    self.page.on("dialog", accept_dialog)
    try:
        with self.page.expect_response(lambda r: "upload-json" in r.url):
            self.page.locator("button[type='submit']").click()
    finally:
        self.page.remove_listener("dialog", accept_dialog)
    self.side_panel.should_be_closed()
    return dialog_messages

3. Decisions for review

  • Confirm on Open, not on opening the panel. Opening the panel discards nothing, and guarding the submit covers both entry points (toolbar and picker) with one attribute.
  • Wording chosen server-side from the slot count. Alternative: one generic string for both sessions. Rejected because "both modelings" confuses a single-modeling session, where a comparison file replaces the current modeling and adds a second one. Cost: one conditional in the view.
