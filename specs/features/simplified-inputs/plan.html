Reuse constructor signatures and class metadata directly. Extract only dotted-path resolution and the timeseries builder-support lookup; add simplified-input eligibility and selection rules on top.

Before implementation · discovery and rendering were mixed together
  • adapters/forms/form_field_generator.py: generate_dynamic_form() reads constructor signatures, unwraps optional annotations, reads list_values/conditional_list_values, then creates field dictionaries containing labels, widgets, values and provenance. It also applies form-specific exclusions and ordering.
  • The same function resolves dotted depends_on paths, but turns them into dynamic_lists for one form: DOM controller IDs and option lists. On edit, a skipped relationship is treated as fixed. That output cannot tell us which fields on other objects must also be exposed.
  • adapters/forms/timeseries_builder_registry.py already owns editable strategies. build_timeseries_form_config() matches the current value to a registered builder before generating its editor context; an unfamiliar value stays read-only.
Refactor · share two helpers, leave metadata access alone

Forms and the new service both use the existing get_init_signature_params(), domain/type_annotation_utils.py and class choice dictionaries. No new metadata wrapper is needed.

Conditional paths: resolve_input_path() now holds the traversal previously embedded in generate_dynamic_form(). It returns the final owner and attribute so forms can read its value and simplified inputs can identify its address.

domain/conditional_inputs.pyImplemented dotted-path owner resolution · abridged

def resolve_input_path(root, path: str) -> tuple[ModelingObject, str]:
    *relationships, attribute = path.split(".")
    owner = root
    for name in relationships:
        owner = getattr(owner, name)
    return owner, attribute

Normal forms retain labels, widgets, provenance, exclusions, ordering and one-hop dynamic_lists. On creation, resolve the remaining path from each candidate reference; on edit, start from the existing object. This extraction leaves existing choice behavior unchanged.

Timeseries support: in adapters/forms/timeseries_builder_registry.py, extract find_editable_builder(annotation, value) from build_timeseries_form_config(). Rendering and eligibility use that same lookup, but only rendering initializes strategy drafts. The existing registry stays the single source of editor support.

adapters/forms/timeseries_builder_registry.pyImplemented shared lookup and editor-support predicate · abridged

def find_editable_builder(annotation, value) -> TimeseriesBuilderDefinition | None:
    return next(
        (builder for builder in editable_builders_for(annotation)
         if isinstance(value, builder.builder_class)),
        None,
    )

def can_edit_timeseries(annotation, value) -> bool:
    return find_editable_builder(annotation, value) is not None

Optional quantities · one contract for ordinary and simplified forms

get_expected_input_unit() first uses a quantity in the class defaults; otherwise it reads InputUnit metadata on the annotated quantity member of the constructor union. get_init_signature_params() still returns ordinary resolved types for existing callers. An empty class default supplies no unit. Missing both sources raises a descriptive type error naming the class and parameter, including when the submitted value is empty; there is no implicit dimensionless fallback.

[IMPL-DECISION-05] — VALIDATED

Run B, Task 7 review — transport limit: the old Configure form gave every eligible field a named help textarea, even if its help was blank and the field was excluded. With 61 Servers and their Storage, those controls alone exceeded Django's 1,000-parameter POST limit before the view could validate the definition. These were configuration controls, not the modeling's numeric values; Configure only displays value previews.

  • Browser: the Configure form sends CSRF as its ordinary field. At htmx:configRequest, definitionFromForm() scans the controls and includes a field only when it is selected or has nonempty help, then adds title, guidance and these sparse field settings as one JSON definition parameter. Excluded fields with blank help are omitted. The controls remain the sole draft state.
  • Server: save_simplified_inputs() decodes that parameter and passes a complete replacement to UpdateSimplifiedDefinitionUseCase.execute(), which completes required companions, validates dependencies and persists interface settings. Other omitted fields are excluded; retained help on an excluded field survives only if that field is present in the definition.

Sending only selected fields would erase help intentionally kept on excluded fields; the current JSON already omits excluded fields without help. The Django parameter limit remains unchanged, while the number of POST parameters stays bounded even when many fields are selected. Browser serialization tests cover the sparse definition and retained help; the large-model view regression saves more than 1,000 selected fields through one JSON parameter.

Before leaving a dirty Configure form, offer Save / Discard / Stay. Save continues the requested action only after success; failure keeps the form open. This also gates model switching, Compare, Results/Sources, file opening and export. Thus inline bookmarks cannot save alongside a Configure draft; no reconciliation is needed.

Each Configure entry loads saved settings, starts at the top, opens the first object and turns the selected-object filter off. Do not park its draft or restore its layout after leaving. Clear, after confirmation, empties the form's field settings; Save replaces the saved fields with that empty selection. Ordinary deselection retains help.
