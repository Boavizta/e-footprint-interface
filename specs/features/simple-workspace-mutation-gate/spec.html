Simplified-input save lock

Spec revised for review · 13 October 2026 · Interface-owned

This replaces the earlier cancellation proposal in this feature folder. The implementation plan is a separate review artifact.

1. Problem and audience

The current workspace-wide interaction guard grew substantially when Simplified-input autosave was added. Expected editing is sequential and saves are usually short; that is an assumption, not a measured latency guarantee. People editing a model can wait briefly for a save to finish. The goal is to retain clear save feedback with less browser coordination.

2. Success criteria

  1. Completing a valid Simplified-input value or provenance edit starts its ordinary save with the submitted value intact. During that request, buttons other than Export and Simplified-input fields are unavailable to the user. The interface adds no queue or retry for a blocked edit.
  2. On success, failure or transport error, the controls become usable again. Controls that were unavailable because of a real prerequisite remain unavailable. Existing Saving, Saved and Not saved feedback and accepted-value restoration on server rejection still work.
  3. Reading, navigation and other controls need not remain usable during the brief save. Existing unsaved-form confirmation and domain constraints still apply when interaction resumes.
  4. Export remains available during a Simplified-input field save and downloads the saved repository state without waiting, forcing the edit to save, or continuing later. The file may include that edit if its save reaches persistence before the export request is handled; it is never built from the unsaved browser field. Dirty Configure still blocks export, and clean Configure exports in place.

3. Scope

Replace the broad browser interaction lock with a small lock for Simplified-input field saves. Existing Modeling, Configure, bookmark, diagram and card-order actions keep their own request behavior. This feature no longer promises one active write across the entire workspace or cancellation feedback for every overlapping action.

No save queue, automatic retry, new draft store, cross-tab coordination or server persistence redesign is introduced. Server validation, accepted-state ownership and error presentation remain as they are.

4. UX / interface

5. Constraints

Favor the browser and HTMX's native disabling behavior. Preserve the project's HTMX-first rule, lean feature priority, the rendering and workspace contracts, and the existing saved-state export boundary.

The older Simplified-input requirement for broad workspace locking must be reconciled when this replacement is implemented. The previous cancellation specification in this folder is superseded by this document. Allowing export during a save changes the busy-export clause of the earlier export specification; its saved-state and dirty-Configure rules remain.

6. Open questions

No further product decision is needed for planning.

7. Resuming from cold context

Read this spec, then the plan. Follow the architecture router and preserve unrelated local changes. The feature remains in review; do not generate tasks or implement it without a later request.
