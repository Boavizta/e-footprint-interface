Simple workspace mutation gate

Spec — under review · 8 October 2026 · Interface-owned

This feature replaces comprehensive save-time interaction locking with a small cancellation policy. The user authorized this specification and a draft plan; application implementation and implementation tasks require later review. Refine the draft with spec-plan in a fresh session.

1. Problem and audience

Simplified-input autosave currently prevents editing, structural actions, navigation and export across the workspace during a save. Coordinating those controls has substantially increased browser-code complexity.

The expected usage is sequential editing with usually low request latency. This is a working assumption, not a measured latency guarantee. Occasional overlapping actions should receive clear cancellation feedback; optimizing rapid input through queues or comprehensive interaction locking is not a priority.

The audience is people editing models through Simplified inputs, Modeling, Sources and Results. The goal is a smaller, understandable implementation with predictable behavior when saves overlap.

2. Success criteria

  1. Within one browser workspace, only one operation that writes workspace state can be active at a time. An overlapping write is canceled before transmission; the first operation continues normally.
  2. The canceled operation never runs later automatically. A concise notice explains that another save was running and asks the user to try the action again after it finishes.
  3. A canceled field save is marked Not saved, rather than Saved or indefinitely Saving. While its editor remains present, its attempted value stays available for manual resubmission through the ordinary edit-completion action. Finishing the first save does not submit it.
  4. The workspace does not blanket-disable editing or harmless navigation during a save. Reads, previews, reading and scrolling remain available. Existing prerequisites and unsaved-form confirmations still apply.
  5. An export attempted during an active write does not download an older snapshot. It receives busy feedback and can be activated again afterward. Existing focused-field save-before-export behavior remains.
  6. Success, rejection and transport failure all release the active-operation state. A later action works normally, and a concurrent read cannot release another operation's gate.

3. Scope

Apply the cancellation policy to existing workspace writes, including input and metadata saves, configuration saves, object and relationship changes, model switching/replacement, card order and diagram settings/deletion. Read-only actions and stateless previews do not occupy the write gate.

Keep feedback local where an existing field status is available, with one concise notice for the action. An overlap is a busy-workspace cancellation, not a server validation error.

Queueing, automatic retries, background resubmission, a new draft store, generic request middleware, cross-tab coordination and backend persistence redesign are outside this feature. No durability is promised for a canceled value across leaving or replacing its editor. Existing explicit Configure and bookmark drafts retain their current behavior; this feature does not add navigation guards for canceled field edits.

5. Constraints

Use the smallest extension of existing request and feedback mechanisms. Prefer a central write gate and a narrow export check over coordinating every input and action. Preserve accepted server-side mutations, validation, calculations, HTTP error handling and existing domain constraints.

This intentionally changes the original simplified-inputs requirement to disable further edits, structural actions and view/model navigation while saving. It retains one active write and removes automatic queueing from consideration. The older requirement must be reconciled when this feature is implemented.

The feature stays within the mission and constitution, particularly HTMX-first interaction and minimal JavaScript. Current behavior is described in Rendering, Workspace and Persistence.

6. Open questions

No queue-versus-cancellation decision remains: this draft uses cancellation. Planning should settle notice placement and the smallest integration with existing save statuses. If normal response updates replace a canceled editor, do not invent draft-preservation machinery; show the concrete interaction and resolve the behavior with the user before expanding scope.
