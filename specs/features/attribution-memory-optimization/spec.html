Attribution memory optimization

Status: Approved direction · 2026-08-28

Problem

Cold attribution calculations retain large hourly intermediates for every impact source at once. On realistic, long-running systems with several usage patterns, this can consume multiple gigabytes even though the final Sankey matrix contains only period totals and an attributed footprint contains only one hourly result.

Success criteria

  • Cold Sankey peak memory is substantially reduced without changing its rows, graph, cache behavior, or UI.
  • attributed_footprint(obj, phase) retains its signature, hourly numerical result and explainability, while avoiding simultaneous retention of unrelated sources' attribution intermediates where feasible.
  • Reactive invalidation remains correct after intermediate values are released.
  • Fresh-process benchmarks cover representative four- and five-pattern smart-building systems and compare peak RSS, latency and computation count.
  • The interface continues to receive the same library results; this feature introduces no intentional UX change.

Scope

In scope: source-scoped lifetime reduction for Sankey and direct attributed-footprint calculations, correctness tests, repeatable memory measurements, and interface dependency/production validation. Out of scope: changing model semantics, removing hourly attributed footprints, weakening formulas, pre-calculation memory prediction, or replacing the reactive memory guard.

Constraints

  • The e-footprint library remains the owner of attribution and reactive-cache behavior.
  • Cached descendants must still invalidate when an evicted upstream intermediate changes.
  • Memory improvements must not depend on cyclic garbage collection timing.
