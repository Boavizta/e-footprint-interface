Attribution memory optimization — Implementation plan

Status: Attributed-footprint experiment viable; formula presentation decision pending · 2026-08-28 · Spec: spec.html

1. Approach

The common principle is to reduce each impact source to the result required by its caller, then release that source's attribution-only hourly intermediates before moving to the next source. The reactive graph retains dependency edges independently of cached values, so releasing an intermediate must drop its value without invalidating a coherent descendant or losing the edge that will invalidate that descendant after a future input edit.

For Sankey, each source already exposes impact_repartition_rows: JSON-native rows whose values are period sums in kilograms. System.impact_repartition_matrix appends one source's rows and immediately evicts that source's explicitly marked transient structures. The final matrix stays cached and serializable. This changes lifetime, not calculations: the same source slots execute, and a later edit recomputes the affected source rows plus the transient helpers that were deliberately released.

For attributed_footprint(obj, phase), first test a source-wise fold while keeping the public signature. For each source, aggregate only atoms whose chain selects obj, finalize the subtotal's existing formula in the same manner as a calculated attribute, clear arithmetic parents, and evict the source's transient structures. Measure whether the retained formula or direct-ancestor metadata still strongly references evicted hourly values. Do not weaken formula/explainability semantics merely to obtain a benchmark win. If formula references prevent release, document the retention path before considering a lightweight address-based formula representation.

4. Correctness and performance gates

  • Compare complete Sankey matrix rows and rendered node/link payloads before and after optimization.
  • Verify an evicted upstream transient slot is empty, its cached descendant remains readable, and an input edit still invalidates that descendant through the preserved edge.
  • Compare attributed hourly magnitudes, unit, start date, label, sum and displayed formula before/after.
  • Measure each scenario in at least three fresh processes; report medians and individual outliers.
  • Run the complete library suite. The current Sankey experiment passes 1,506 tests, 9 skips and 67 subtests.
  • Run an interface Docker benchmark before changing the deployed dependency.

5. Risks and alternatives

  • Formula presentation: the current on-demand result never runs calculated-attribute finalization, so explain() renders an empty expression. Progressive finalization preserves the complete formula and releases parents, but exposes a 337,627-character expression for the reference usage result. Decide explicitly whether fixing that pre-existing empty-formula behavior belongs in this optimization or needs compact display.
  • Repeated direct reads: source eviction can trade memory for recomputation on later calls. Keep the single-object API; do not introduce an unbounded batch signature to hide that cost.
  • Largest-source bound: source scoping cannot prevent a single source calculation from exceeding capacity. The reactive memory guard remains the final safety mechanism.
  • Matrix-only attributed totals: folding scalar rows is simpler and cheaper but cannot replace the documented hourly return contract, so it is not the primary approach.

6. Architecture and documentation

All modeling and cache-lifetime changes belong to e-footprint. The interface owns only profiling evidence, dependency adoption and deployment validation. No schema or database migration is required. If the transient computed structure pattern ships, document it briefly in the library architecture/contributor guidance so future calculations do not accidentally retain attribution-only arrays.

7. Attributed-footprint experiment outcome

Three fresh processes per scenario produced identical float32 hourly bytes, dates, units, labels and period sums between clean dev and the optimized function. Source eviction alone is insufficient for repeated targets: five retained usage results peaked at 2,423 MiB because their arithmetic parents kept each recomputed generation alive. Composable formula finalization held the same five-result run to 657 MiB, versus 2,344 MiB on clean dev, with latency increasing from 1.66 to 2.33 seconds. The full library suite passes: 1,507 tests, 9 skips and 67 subtests.
