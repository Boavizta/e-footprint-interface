# Feature backlog

This folder parks tentative features and architectural problems that are worth preserving but are not ready for the
specify → plan → tasks → implement workflow.

Each topic lives in its own folder and should capture:

- the observed problem and evidence;
- why it is not being addressed now;
- known constraints and rejected shortcuts;
- the questions that must be answered before promoting it to `specs/features/`.

Backlog notes are investigative context, not approved requirements or implementation plans. When a topic becomes active,
create a feature spec under `specs/features/` and carry forward only the still-valid findings.
