Workspace / multi-slot session

The session holds a workspace of up to two model slots plus an active-slot pointer, not a single model (model-comparison feature). A single-model session is the degenerate case: one slot [0], active 0 — behaviourally identical to before.

  • IWorkspaceRepository (domain/interfaces/) is the slot-index port: list_slots, active_slot, set_active_slot, add_slot(system_data) → slot, remove_slot, repository_for(slot) → ISystemRepository. ISystemRepository stays a single-model abstraction, now slot-targeted. Implementations: SessionWorkspaceRepository (production) and InMemoryWorkspaceRepository (integration harness) — interchangeable per constitution §1.2.
  • Slot-aware cache keys. SessionSystemRepository is bound to a slot (defaulting to the active slot, so the existing call sites resolve through SessionWorkspaceRepository(session).active_repository() unchanged) and keys its payload system_data:{session_key}:{slot} for all slots (symmetric). Slot 0 carries a one-release legacy read-fallback: an in-flight pre-workspace payload under the old unsuffixed system_data:{session_key} key is read once, written through to the suffixed key, and the legacy key deleted (see version_upgrade_handlers.py; removed next release).
  • Shared payload budget. The tiny workspace index (slot ids + active + each slot's last-saved with-calc byte size) lives in the session via WorkspaceIndex; the heavy per-slot payloads stay in the cache. MAX_PAYLOAD_SIZE_MB is enforced as a shared budget over the summed with-calc weight of all slots (sibling sizes read from the index — the untouched slot is never re-serialized), so editing one model never deserializes the other (binding Redis-RAM / JSON-round-trip constraint).
  • Index↔cache TTL reconciliation. The index lives in the long-lived session, but each slot's payload lives in the cache with far shorter TTLs (Redis one hour by default, Postgres the selected recovery duration), so a returning user's index can list a slot whose payload has expired. WorkspaceRepositoryBase.drop_expired_slots() (called by model_builder_main before hydrating any slot) forgets such slots so the workspace collapses to its surviving model(s) and the active pointer follows onto a survivor; an empty active slot is then re-seeded to the scratch baseline. Without it, build_workspace_slots hydrates the empty slot and reads .system on an un-hydrated ModelWeb, raising SessionExpiredError outside the entry view's try/except → 500.
  • Distinct-system-id invariant. Two slots must never hold the same system id (the web_id DOM prefix depends on it). WorkspaceRepositoryBase.add_slot is the single enforcement point: on any cross-slot id collision it mints a fresh system id via the library efootprint.comparison.duplication.assign_fresh_system_id (deserialize → re-id → reserialize), preserving every object id so the comparison diff still pairs by identity. This covers every add path (import, workspace import, example, blank, duplicate). The in-place write paths (example-load / import into an existing slot) call WorkspaceRepositoryBase.distinctify_against_siblings for the same guarantee.
  • Comparison file (.e-f.json). An additive envelope { efootprint_workspace_version, active_slot, models: [<doc>, <doc>] } where each models[] element is a byte-for-byte complete single-model document (the same download_json payload, including its own interface_config) — so the single-model format is never re-implemented or altered. download_workspace (views.py) produces it; _single_model_document(repository) is the shared per-slot builder; _restore_workspace (views_workspace.py) consumes it.

One unified "Open file" upload (upload_json) ingests either format and content-routes on the models key (authoritative): single-model and comparison files share the .e-f.json extension, so content is the only signal — a comparison file ⇒ _restore_workspace restores both slots + the active pointer; a single-model file ⇒ replace the active model.

On import each model is recomputed (SystemImportService) and the second slot is added through add_slot, so the shared budget and the distinct-system-id invariant both apply (the two embedded models may legitimately share an id); each restored slot's interface_config is re-attached so Sankey settings survive per model (with_fresh_system_id carries the interface-only metadata across a re-mint). The single toolbar Open file entry renders in every session, closing the gap where a single-model session could not open a comparison file; Download keeps the two-granularity menu (this model / both models) only when two models exist (a single-model session has just one model to export), so its plain download-json/ link and E2E selector stay unchanged.

Adding a second model from a file is a distinct intent kept on the tab strip ("+Add → Import from file…", single-model files only) — "Open file" opens-into-here, "+Add → Import" adds-as-second.

Duplication copies repository-owned interface settings independently and remaps any simplified-input field address owned by the newly minted System; ordinary object addresses stay unchanged. It starts from the complete ModelWeb document, including objects not yet connected to usage. Re-ID uses SystemImportService.serialize_system_and_orphans() to retain those objects and their selected inputs. Workspace opening prepares every incoming model through SystemImportService, resolves incoming System-ID collisions, and checks the summed final payload size before clearing any live slot. Its slot-0 inputs-only recovery document is prepared before replacement too. Settings are validated when authored; file opening preserves them without a second definition validation.

Two resident canvases and DOM identities

The builder hosts the tab strip (components/model_tab_strip.html) above the per-model action toolbar (upload_download_reboot_model_tooltips.html), which sits above one resident canvas per slot — model_builder_main.html includes the strip before the toolbar so the model selector reads as the parent of the model-scoped controls (browser-tab pattern: tab strip, then the active tab's toolbar). model_builder_main.html loops workspace_slots, rendering a #model-canva-{slot} (with data-model-canvas="{slot}") per occupied slot, the active one visible and the others d-none. Switching is client-first (mirrors the Results/Sources show/hide pattern): the switch-model endpoint flips the active slot server-side and OOB-rebinds the small shared chrome (#system-name, results buttons, edge toggle) — every switch lands on the resident builder (the comparison view, if open, is dismissed client-side first), so the chrome targets are always present. Meanwhile model_comparison.js toggles canvas visibility on the switchModelCanvas trigger — no canvas re-render, so transient canvas state survives.

On the builder, shared #sidePanel, #helpDrawer, and the results panel stay singletons bound to the active slot. Their open content (an object's edit form, a class help page, a model's chart) belongs to the model being left, so switching closes all three — otherwise they linger over the now-active canvas (and a side-panel save would target the wrong model; an OOB-rebound "Results" bar would float mid-air over the still-open stale panel). switchToSlot (model_comparison.js) closes the side panel (closeAndEmptySidePanel() when not d-none) and collapses the results panel (hidePanelResult() when #result-block has content, the open-signal that survives the results-button OOB rebind); the help drawer self-closes from its own module on the same switchModelCanvas event (respecting help_drawer_utils.js's "nothing escapes to window" encapsulation).

Every switchModelCanvas listener still null-guards absent elements (presence-checks before touching classList), a holdover that costs nothing now that every switch runs against the resident builder.

Navigating away with unsaved side-panel edits is gated before it fires. side_panel_utils.js hooks htmx:confirm (which precedes the request) and, while formModified, defers any request whose path is in PANEL_DISCARDING_PATHS behind the shared unsavedModal — "Continue" re-fires the exact request via event.detail.issueRequest(true) (no re-confirm), "Cancel" never issues it so the panel and edits survive.

The set is the model switch (/switch-model/) and the +Add actions — Duplicate/Blank (/add-model/) and Import (/open-add-model-import-panel/). These are matched as request URL path segments, not Django route names, and are slash-delimited so /add-model/ can't partial-match /open-add-model-import-panel/. Matching on the path (not a DOM element) covers every entry point — tab strip, mobile pill, burger — and works for both attribute-driven requests and htmx.ajax calls (Import).

The older htmx:beforeRequest guard only covers #sidePanel-targeted requests; these navigations don't target it (the switch POSTs to itself with hx-swap="none", +Add swaps #main-content-block or opens via htmx.ajax), hence the separate htmx:confirm hook.

Opening Compare (/compare/) is deliberately NOT in the set — it is non-destructive: the comparison view is a resident sibling, so the side panel survives hidden behind it and a same-slot return resumes it intact (opening Compare discards nothing). A cross-slot dismiss does discard, but the capture-phase model-tab handler in model_comparison.js tears the dashboard down first (revealing the edited model) and then lets /switch-model/ proceed — which IS guarded — so the unsaved modal lands over the revealed model, not over the comparison; a same-slot dismiss is preventDefaulted (no POST, no warning).

reset/example-load are deliberately exempt — they obviously discard the current model, so a separate unsaved warning would be noise. remove-model also discards the panel but keeps its own destructive window.confirm (model_comparison.js) rather than going through the modal — to avoid stacking two dialogs on one click, that single confirm is made unsaved-aware instead (it appends an unsaved-changes warning when window.isSidePanelFormModified(), the read-only flag getter side_panel_utils.js exposes for exactly this).

Simplified-input workspace and Configure exits

Each slot has a surviving #simplified-slot-{slot} target beside the resident canvases. Modeling → Simplified inputs always reads fresh state; simplified_inputs.js remembers only the last base view by System ID. A successful JSON load supplies one-use session opening markers, consumed by the next builder render: selected inputs open Simplified inputs, an empty selection opens Modeling. Ordinary slot switches never reapply this rule.

A failed simple autosave keeps its resident field retryable. Entry into Modeling or Configure requires correction, retry or explicit Discard edit first, so fresh rendering cannot silently replace a failed draft. Model tabs may still park it; export of both models checks these resident failures.

Configure renders all eligible fields using the same type/object hierarchy, a single main scrolling pane, container-responsive field columns and compact object selector. Draft settings live only in form controls with one form-level dirty flag. Filtering hides objects and matching navigation entries without dropping controls or help; recursive dependency locks use catalog links. Save serializes the complete definition directly from the controls into one JSON form parameter, including checked locked inputs, so model size does not exhaust Django's parameter limit. Every exit (including Results/Sources, Compare, switching, import and download) uses Save/Discard/Stay. Discard fetches saved state before continuing; Save continues only after the matching successful mutation settlement. Cancelled or failed saves leave the draft visible. The ordinary side-panel discard-confirmation helper runs before focused-view reads, whose continuation is tied to their actually issued XHR. Duplicate reads are suppressed; leaving or starting a mutation aborts pending reads before they can replace a draft or park Configure in another model's resident target. Configure is never parked and each entry starts fresh.

Tab roles and ordering

Tabs are fixed role labels; the model name lives in the toolbar. Each model tab shows a fixed label by list position — first slot "Reference model", second "Comparison model" (matching how compare() pairs workspace_slots[0]→A, [1]→B) — not the model's own name, so a long name can never stretch a tab (the tab width is pinned in custom.scss).

The slot list is role-ordered, not numeric-ordered: WorkspaceIndex (and the in-memory mirror) append new slots and never sorted() the list, so removing the Reference (slot 0) leaves the survivor role-first in slot 1, and a model added afterwards reuses the freed slot number 0 yet appends as the Comparison — sorting would re-promote it to Reference (the model-comparison re-add bug). The active model's editable name lives in the toolbar (#btn-change-system-name / #system-name, left of the edge toggle); renaming swaps #system-name in place and switching OOB-rebinds it (above).

Mobile navigation

On mobile (<lg), the strip moves into the burger; switching lives on a role pill. The fixed-width tabs overflow a phone, so on <lg the builder hides the tab strip (d-none d-lg-flex) and surfaces its functions in the toolbar's burger menu (items marked d-lg-none so they never leak into the inline desktop navbar-expand-lg): a "Models" group holding ⇄Compare (two models) or the +Add options (one model).

Switching moves to an always-visible active-model pill beside #system-name (components/active_model_role.html) — a dropdown that shows the active role and offers "switch to the other model". The pill is a sibling of #system-name (never a child), so the rename (innerHTML) and switch (outerHTML) swaps of #system-name never disturb it; switch_model rebinds the whole pill via its own OOB fragment (the partial rendered with oob=True / hx-swap-oob="true"), so both the label and the switch-to target track the now-active slot — the same partial serves the inline toolbar include and the OOB rebind (single source of truth, the results_bar_button.html pattern).

While the comparison view is open the toolbar/burger is hidden, so the SCSS reveals the one builder strip on <lg (body.comparing #model-tab-strip → flex-nowrap overflow-x-auto) — ⇄Compare is hidden on mobile while comparing (body.comparing .model-tab--compare → display:none), leaving only the two fixed-width model tabs, so both fit at once. On desktop the ⇄Compare tab stays, highlighted as the active destination. The mobile burger's ⇄Compare entry swaps into the resident #comparison-view (the same flow as the desktop tab), so the builder is hidden, not destroyed. Desktop is otherwise unchanged — the tab strip owns all of this.

DOM identity and OOB targeting

DOM-id collisions between the two canvases are prevented two ways:

  • Object-card ids flow from ModelingObjectWeb.web_id, prefixed once at the root with sys-{system id}- (the _system_web_id_prefix chokepoint). Every derived id (button-/flush-/icon-), HTMX/hyperscript selector, leaderline anchor and mirrored-card ref inherits the prefix; the nested branch inherits it through parent_container.web_id, so it is applied exactly once. The literal sys- is load-bearing — system ids are uuids that often start with a digit, and HTMX resolves OOB targets with querySelector('#'+id), which throws on a leading-digit id; the constant letter prefix keeps every id a valid selector. __hash__/__eq__ are system-scoped as a consequence. Routing is unaffected (URLs use the separate efootprint_id; form-field names are {class}_{attr}).
  • Structural canvas ids (lists, containers, add-buttons) are not web_id-derived, so they would collide. The active canvas renders them with their canonical ids (up-list, btn-add-server, …) so every existing add/edit flow, Sortable, the tour and the E2E selectors keep working unchanged; a parked canvas suffixes them -{slot} (driven by slot_suffix/is_active_canvas passed into model_canvas_content.html, each element tagged data-canvas-id). On switch, model_comparison.js#rekeyCanvas migrates the canonical ids (and data-tour-targets) to the newly-active canvas, then reinitializes Sortable against those newly canonical lists; a drag save therefore always targets the active repository while each parked canvas retains its separately rendered saved order.

OOB correctness: oob_regions.py's model_canvas (and edge_device_lists) regions emit the active slot's #model-canva-{slot} / canonical list ids — a mutation always targets the active slot, and HTMX OOB is first-match-by-id, so it never lands in the parked canvas. Leader lines build only for the visible canvas: leaderline_utils.js already resolves endpoints inside a d-none subtree to null, so the hidden canvas's lines are skipped, and the switch re-runs initModelBuilderMain to draw the now-visible canvas's lines. CSS that targeted the old single #model-canva now targets [data-model-canvas] (compiled from scss/custom.scss).
