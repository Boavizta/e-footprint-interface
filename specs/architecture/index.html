Architectural map

Django views parse HTTP input; application use cases orchestrate web wrappers and domain services; efootprint owns modeling truth. Presenters and templates turn results and side-effect descriptors into HTMX responses, including out-of-band (OOB) swaps. Inner layers do not import Django or adapters.

Repository and description ports

The session indexes up to two model slots. Redis holds canonical cached state; Postgres holds inputs-only recovery. Each slot has a resident canvas, with shared active-model controls and a resident comparison dashboard.

Cross-cutting boundaries

  • Domain invariants and calculations belong to the library; adapter validation handles transport and immediate UX.
  • ModelWeb serializes domain state; repositories own interface_config and slot persistence.
  • Mutations emit OOB descriptors; presenters resolve them to the active canvas and shared controls.

For library behavior, use the library architecture index. For user journeys, use the design hub. Style and tests live in conventions and testing.
